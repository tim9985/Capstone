## 1. 두 층

| 층 | 언제 | 방법 |
|---|---|---|
| **짧은 연결** | 화면 안에서 연속으로 보이는 동안 (초당 5장이면 0.2초 간격) | **추적기**가 같은 영상 ID 로 잇는다 |
| **긴 연결** | 화면에서 사라졌다가 수십 초 ~ 수 분 뒤 다시 보일 때 | 위치·시간 → 상의 색상 → (선택) 재식별 순서로 기존 후보인지 판단 |

## 2. 짧은 연결 — 드론이 움직여서 생기는 문제

일반 추적기(ByteTrack)는 이전 박스와 새 박스가 **겹치는 정도**([[IoU]])로 잇는다.

- 초당 5장이면 **사람 박스가 자기 크기보다 더 많이 움직인다**
  - 고도 30 m · 초속 5 m → 0.2초에 1 m → 1920 원본에서 **약 63 px** 이동
  - 서 있는 사람은 약 **31 px** → 박스가 전혀 안 겹친다 → 매 프레임 새 사람으로 잡힌다
- 해결
  - **카메라 움직임 보정 (GMC)** — 배경이 움직인 만큼을 광학 흐름으로 계산해 뺀다. Ultralytics 8.4.102 `botsort.yaml` 에 `gmc_method: sparseOptFlow` 가 있다
  - **지도 좌표에서 추적** — 박스를 매 프레임 땅 좌표로 바꾼 뒤 땅 위에서 잇는다. 사람은 거의 안 움직여서 잘 맞는다
- `drone_yolo/tracker_ab.py` (광학 흐름 · ByteTrack · BoT-SORT 비교)는 시뮬레이터 기준 → **초당 5장 실영상으로 다시 재야 한다**

## 3. 관측 건수 세기 — "서로 다른 시각"

반복 관측을 유지한다면 **프레임 수가 아니라 관측 단위**로 센다.

> [!failure] 연속 프레임 3장으로 세면 안 되는 이유
> 고도 30 m · 초속 5 m 에서 사람 한 명은 화면에 약 3.5초, 초당 5장이면 **약 17장**에 찍힌다.
> 바위를 사람으로 잘못 잡으면 같은 각도·같은 빛이라 17장 내내 잘못 잡힌다 → **0.6초 만에 "반복 관측"** 이 된다.

| 규칙 | 내용 |
|---|---|
| 유효 탐지 | 신뢰도 0.15 이상 · 안정 프레임 · **탐지기가 실제로 낸 박스** (추적기가 예측만 한 프레임 제외) |
| 관측 1건 | 한 **추적 구간**(화면에 들어왔다 나갈 때까지) 안의 탐지들 → 신뢰도 가장 높은 한 장을 대표로 1건 |
| 오래 머물 때 | 제자리 비행·개별 추적 중에는 마지막으로 센 뒤 **최소 3초 AND 기체 5 m 이상 이동** 해야 1건 추가 (초안 값) |
| 끊겨서 다시 보임 | 4절 판정으로 같은 후보면 1건 추가 |

거리 조건까지 두는 이유 — 같은 자리에서 시간만 흐르면 같은 각도로 같은 오탐을 반복한다.

| 상황 | 건수 |
|---|---|
| 정찰 경로로 한 번 지나감 | 1건 (단발 후보 · 알림은 바로) |
| 옆 경로에서 다시 화면에 들어옴 | 2건 |
| 재관측 요청으로 다른 위치·고도에서 봄 | 3건 |
| 개별 추적 중 계속 따라감 | 3초 · 5 m 마다 1건 |

```python
MIN_GAP_S = 3.0      # 같은 추적 구간에서 추가로 셀 최소 간격 (초안)
MIN_MOVE_M = 5.0     # 그 사이 드론 이동 거리 (초안)

def on_detection(det, frame):
    if not valid(det, frame):                        # 신뢰도 · 안정 프레임 · 실제 탐지 박스
        return
    cand = match_track(det) or match_by_map(det)     # 추적 ID → 없으면 4절 판정
    if cand is None:
        cand = new_candidate(det)
        alert(cand)                                  # 단발 후보라도 바로 알림
    last = cand.last_counted
    new_segment = det.track_id != last.track_id
    enough = (frame.t - last.t >= MIN_GAP_S and
              dist(frame.drone_pos, last.drone_pos) >= MIN_MOVE_M)
    if new_segment or enough:
        cand.observations.append(det)                # 관측 1건
        cand.last_counted = det
    else:
        cand.update_best(det)                        # 같은 관측 안에서는 대표 장면만 갱신
```

## 4. 긴 연결 — 끊긴 뒤 같은 사람인지

| 순서 | 단서 | 판단 |
|---|---|---|
| ① **필수 조건** | 지도 위치 · 시간 | 두 좌표의 **오차 범위가 겹치나** · 경과 시간 동안 **보행 속도로 갈 수 있는 거리 안인가**. 쓰러진 요구조자는 거의 안 움직여서 대부분 여기서 해결된다 |
| ② 점수 | 상의 색상 | 12색 1·2순위 확률 비교. 빨강 ↔ 파랑처럼 명백히 다르면 합치지 않는다 → [[10 상의 색상 비교]] |
| ③ 선택 | 재식별(ReID) 임베딩 | 5절 |
| ④ 판정 | 후보 여럿이면 점수 합으로 짝짓기 (헝가리안 할당) | **애매하면 합치지 않는다** |

> [!important] 합치는 오류가 나누는 오류보다 위험하다
> 두 사람을 한 명으로 합치면 **한 사람을 놓친다**. 한 사람을 둘로 나누면 **후보가 하나 중복**될 뿐이다 → 기준은 보수적으로.

## 5. 딥러닝 재식별 (Person Re-Identification)

**원리** — 모델이 사람 크롭을 숫자 벡터(예: 512차원)로 바꾼다. 같은 사람끼리 벡터가 가깝도록(triplet loss 등) 학습되어, 두 벡터의 **코사인 유사도**가 높으면 같은 사람으로 본다.

| 도구 | 내용 |
|---|---|
| Ultralytics BoT-SORT | `botsort.yaml` 에 `with_reid` · `appearance_thresh` 옵션. `model: auto` 면 탐지 모델 특징을 쓴다 |
| torchreid · FastReID | **OSNet** 같은 가벼운 재식별 모델 |

> [!failure] 우리 조건에서 약한 이유
> | 조건 | 문제 |
> |---|---|
> | **시점** | 공개 재식별 데이터(Market-1501 등)는 지상 CCTV 측면. 하향 90° 에선 머리·어깨만 보여 배운 단서(얼굴·하의·신발·체형)가 없다 |
> | **크기** | 원본에서 서 있는 사람 31~59 px → 무늬·로고 없음, 사실상 색과 윤곽뿐 |
> | **자세** | 서 있다가 누우면 모양이 완전히 달라진다 |
> | **비슷한 옷** | 등산복 색이 흔하다 |

항공 재식별 공개 데이터도 있지만(PRAI-1581 · AG-ReID 등) 대부분 비스듬한 시점이라 **우리 하향 영상에서 효과는 직접 재야 한다**.

## 7. 추천 순서

1. **BoT-SORT + GMC** 를 초당 5장 실영상(Okutama 등)에 돌려 추적이 얼마나 끊기는지 본다
2. **위치·시간 조건 + 상의 색상** 으로 끊긴 추적을 규칙 기반으로 재연결한다 — 요구조자 수색은 이것으로 충분할 가능성이 크다
3. **재식별 임베딩** 은 NOMAD 쌍 시험에서 색상보다 확실히 나을 때만 더한다 (필요하면 자체 촬영 크롭으로 파인튜닝)
