> [!abstract] 한 줄
> **기본 지도** = "어디에 무엇이 있나" (배경) · **상황지도** = "이번 임무에서 무엇을 봤고 무엇을 찾았나" (임무 상태).
> 사용자 UI 는 기본 지도 **위에** 상황지도를 겹쳐 보여주는 창이다.

## 세 가지의 관계

| 구분         | 무엇                             | 요구명세서                            | 바뀌는 시점  |
| ---------- | ------------------------------ | -------------------------------- | ------- |
| **기본 지도**  | 위성·기본지도, 건물 윤곽·높이, 지형 (VWorld) | UCD-03 지도 조회·이동·레이어·좌표 변환        | 거의 안 바뀜 |
| **상황지도**   | 이번 임무의 관측·탐지 결과를 좌표 위에 쌓은 정보   | UCD-08 상황지도 조회·관측영역 계산·관측 이력·완료도 | 촬영할 때마다 |
| **사용자 UI** | 둘을 겹쳐 보여주는 웹/PWA 화면            | UI-02 지도·임무 설정 · UI-04 실시간 관제    | —       |

관제 화면 예: 뒤의 위성 사진·건물 = 기본 지도 / 노란 구역·경로, 관측 지점, "상황 지도 갱신 — 완료 관측 1/34" 패널 = 상황지도

## 상황지도가 보여주는 것
1. **기체와 경로** — 현재 위치, 계획 경로 · 실제 경로
2. **사람 후보** — 탐지 위치와 오차 범위. 좌표 보류 후보는 확정 위치로 찍지 않음
3. **영역별 관측 상태 5종** — 미관측 · 유효 관측 · 품질 부족 · 가림·가시성 미확인 · 운용 제한
4. **정찰 완료도** — 관측 가능 구역 대비 유효 관측 비율, 영역별 관측 횟수·마지막 시각

→ 계산 방법: [[관측 완료도 계산 방법]] · 칸별 상태 판정 절차: [[관측 상태 판정 알고리즘]]

## 왜 따로 두나
1. **탐색 계획의 입력** — 다음 관측 지점·경로(UCD-05)는 상황지도의 미관측·가림 영역을 보고 정한다. 화면 표시용이 아니라 **서버가 계속 갱신하는 데이터**
2. **"못 찾음" ≠ "없음"** — 지나가기만 했거나 가려진 곳의 미탐지를 사람 부재로 판단하지 않도록 기록

> [!quote] 발표용 한 줄
> "기본 지도는 배경이고, 상황지도는 드론이 어디를 제대로 봤고, 아직 못 봤고, 어디서 사람을 찾았는지 기록한 임무 지도입니다. 다음 탐색 경로도 이 상황지도를 보고 정합니다."

## 2.5차원 상황지도는?
| 문서 | 표현 |
|---|---|
| 주제제안서 최종 (09-01) | "정찰 완료·미관측 구역을 **다층(2.5차원)** 구조로 갱신", "VWorld 기반 **2.5차원 MissionMap** 구축" |
| 요구명세서 v1.1 ~ v1.7 | **표현 없음** |

- **2.5차원** = 평면 지도 + 높이 값(건물·지형 높이, 촬영 고도). 완전한 3D 는 아님
- v1.7 에 남은 흔적: "건물 높이 반영해 경로 갱신"(1.2), "건물 윤곽과 높이 표시"(UC-0301), "지형 기준 촬영 범위·가림 확인"(UC-0802)
- 높이 품질을 다루던 공간정보 유즈케이스·비행 경로 계산은 v1.3~v1.5 에서 삭제 → 지금은 사실상 **평면 위 관측 상태**에 가깝다

> [!warning] 팀 결정 필요 (상황지도 = 이시원 담당)
> **A.** 명세서에 다시 명시 — "기본지도 + 건물·지형 높이 레이어 + 관측·가림 상태를 촬영 고도와 함께 누적하는 2.5차원 다층 지도"
> **B.** 범위 축소 공식화 — "2.5차원 표현은 건물 높이 표시와 가림 판정으로 한정"

- 참고: 관제 인수인계 문서의 "2.5D/Depth 지도"는 **시뮬레이터 깊이 영상 HUD** 로 상황지도와 다른 것
