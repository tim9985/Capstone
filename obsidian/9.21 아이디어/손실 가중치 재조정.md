> [!summary] `box 7.5 / cls 0.5 / dfl 1.5` 는 ultralytics 기본값 — **COCO 80클래스·큰 객체** 기준이다
> 우리는 1클래스 · 초소형 · 배경 혼동이 전부다. 같은 배분이 맞을 이유가 없다.

## 우리가 실제로 잰 것

가림 지형 시험셋 · 각 칸 40장 · **가중치 적용 후** 값

| 대상 크기 | box | cls | dfl | 합 |
|---|---:|---:|---:|---:|
| 18 px | 3.755 | **5.174** | 1.868 | 10.798 |
| 34 px | 3.156 | 4.090 | 1.896 | 9.142 |
| 71 px | 2.340 | 3.361 | 1.913 | 7.614 |
| 106 px | 2.236 | 2.395 | 1.724 | 6.356 |
| **106 → 18 증가 (상대)** | +68 % | **+116 %** | +8 % | +70 % |

가중치를 걷어내면 18 px 에서 **raw cls = 10.35** · raw box = 0.50 · raw dfl = 1.25 다.
`cls` 가중치 0.5 가 큰 값을 눌러 놓고, `box` 7.5 가 작은 값을 키워 놓은 구조다.

> [!warning] "손실이 크니 가중치를 올려라" 는 자동으로 성립하지 않는다
> 손실이 크다는 건 **줄일 수 없는 항**이라는 뜻일 수도 있다. 가중치를 올리면
> 이미 못 맞히는 곳에 기울기만 더 쏟게 될 수 있다.
>
> **진짜 근거는 실패 양상이다** — 정밀도@0.15 **0.685** / 재현율@0.15 **0.391**.
> 오탐이 넘치는 게 아니라 **진짜 사람에게 낮은 점수를 주고 있다.**
> 이건 분류 문제지 위치 문제가 아니다.

## 문헌 근거

Psych-Occlusion (arXiv 2412.05553) 은 모델·데이터를 안 건드리고 **손실만 바꿔** 가림 성능을 올렸다.
사람이 수색할 때 **박스를 정확히 맞추려 하지 않고 위치만 본다**는 시각심리 실험을 반영해
박스 경계보다 **중심 좌표 정확도**를 우선했다 → [[문헌 대조 - 비슷한 조건의 공개 실험]]

우리도 같은 조건이다 — **운영자가 스냅샷으로 판단**하고(UC-0705) 채점이 **IoU 0.5** 라
박스 정밀도의 운용 가치가 낮다.

## 후보

| | box | cls | dfl | 성격 |
|---|---:|---:|---:|---|
| 현재 | 7.5 | 0.5 | 1.5 | ultralytics 기본 |
| **A (보수)** | 7.5 | **1.0** | 1.5 | cls 만 2배 — **단일 변수** |
| B (재균형) | **5.0** | **1.0** | 1.5 | 박스 정밀도를 덜 본다 |

**A 부터 한다.** B 는 두 개를 같이 바꿔 원인이 안 갈린다.
A 가 효과 있으면 B 로 더 가고, 없으면 B 도 안 할 근거가 생긴다.

## ⚠ `best.pt` 선정과 충돌한다

`fitness = mAP50-95` 라 **박스가 빡빡해야 점수가 나온다** (ultralytics 8.4.102 · `w=[0,0,0,1]`).
box 가중치를 낮추면 mAP50-95 는 떨어지는데 AP50·재현율은 오를 수 있고,
그러면 **엉뚱한 에폭이 best.pt 로 뽑힌다.**

- 대응: 이 실험은 **`best.pt` 와 `last.pt` 를 둘 다 평가**한다
- fitness 자체를 mAP50 으로 바꾸는 것은 **별도 변수**라 지금 같이 건드리지 않는다
  → [[fitness와 조기 종료]] · [[성능 개선 후보 - AP50 벽]] ②

## 구현

`train_person.py` 에 `--box --cls --dfl` 옵션을 추가해야 한다 (`--translate` 때와 같은 방식).

```bash
python train_person.py --stage 1 --data configs/data_fov.yaml --weights yolo11m.pt \
    --imgsz 1280 --batch 8 --close-mosaic 0 --optimizer SGD --lr0 0.01 \
    --scale 0.3 --translate 0.15 --cls 1.0 --name loss_a_11m --epochs 30
```
