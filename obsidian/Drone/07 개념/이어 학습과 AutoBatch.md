> [!abstract] 한 줄
> 학습이 죽어도 `last.pt` 에서 **그대로 이어** 학습할 수 있다(resume). 배치 크기를 자동으로 고르는 **AutoBatch** 는 편하지만 크게 틀릴 수 있다.

## 체크포인트

| 파일 | 언제 저장 | 쓰임 |
|---|---|---|
| `last.pt` | 에폭이 끝날 때마다 | 가중치 + 옵티마이저 상태 + 학습률 스케줄 위치 + 에폭 번호 + 학습 설정 → **이어 학습용** |
| `best.pt` | fitness 최고 에폭 → [[fitness와 조기 종료]] | 평가 · 배포용 |
| `last_backup.pt` | 자동 복구 서비스가 `last.pt` 를 읽어 본 뒤 복사 | 강제 재시작으로 `last.pt` 가 깨졌을 때 |

- 에폭 **도중**에 죽으면 그 에폭 진행분은 잃는다 — M1 4회차는 15에폭 4 % 지점이라 `last.pt` 는 14에폭 그대로였다

## 이어 학습 (resume)

```bash
yolo train resume model=runs_person/<이름>/weights/last.pt
```

| | 이어 학습 `resume` | 새로 시작 `model=last.pt` |
|---|---|---|
| 에폭 | 멈춘 곳부터 | 0부터 |
| 학습률 · 워밍업 | 스케줄 그대로 | 처음부터 다시 |
| 설정 | 체크포인트에 박힌 값 | 새로 준 값 |

- 설정이 박혀 있어서 노트북 가중치는 Windows 경로 때문에 서버에서 resume 이 안 된다 → [[함정 모음]]
- **`time` 인자** = "몇 시간 안에 끝내라"는 예산. 예산에 맞춰 에폭 수를 줄인다
  - resume 하면 그 시점부터 시간을 다시 재서 남은 에폭이 줄어든다 → M1 은 이어 학습 때 시간 제한을 껐다
- 학습 명령은 재부팅되면 사라진다 → 자동 복구 서비스의 `job.conf` 에 등록해 부팅 후 이어 간다 → [[결정 - GPU 완화 설정과 자동 복구]]

## AutoBatch

- `batch=-1` (메모리 60 % 목표) 또는 `batch=0.85` 같은 비율 → 짧게 시험해 GPU 메모리에 맞는 배치를 추정한다
- **과대 추정 사례**

  | 실행 | 예측 | 실제 |
  |---|---|---|
  | M1 yolo11m @1280 · batch 3 | 16 GB | **6.6 GB** |
  | E1 yolo11s @960 · batch 13 | 19.2 GB | 약 7.2 GB |

- 첫 에폭에 메모리가 모자라면 **말없이 배치를 절반으로** 줄인다 → 실험 조건이 몰래 바뀐다
- → 비교 실험은 배치를 **숫자로 직접** 적고 로그에서 확인한다 (계획 `hyp_v2` 는 batch 16 고정)

## optimizer auto

- 반복(iteration) 수로 최적화 방식을 고른다: 1만 번 미만이면 AdamW, 이상이면 **MuSGD** (ultralytics 8.4.102)
- E1 · M1 은 auto 라 MuSGD 로 학습됐다 → SGD 로 고정한 계획 결과와 직접 비교하지 않는다 → [[5 학습 하이퍼파라미터]]
