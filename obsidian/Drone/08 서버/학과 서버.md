## 재시작 규칙 — `sudo reboot` · `shutdown` 금지

> [!danger] 끄면 다시 안 켜진다
> `sudo reboot` · `sudo shutdown` 으로 끄면 사람이 직접 가서 켜야 한다. 09-12 09:49 ~ 09-14 09:20 **이틀간** 꺼져 있었다.

관리자 공지 방식만 쓴다 → [[sysrq 강제 재시작]]

```bash
echo 1 | sudo tee /proc/sys/kernel/sysrq
echo b | sudo tee /proc/sysrq-trigger
```

- `b` 는 디스크 동기화 없이 즉시 재시작한다 → 먼저 `sync`
- GPU 장애 원인 코드는 재시작 **전에** `sudo dmesg` 로 본다 → [[GPU 장애 코드 Xid]]

## GPU 완화 설정 (09-14 14:22 부터)

| 설정 | 명령 | 되돌리기 |
|---|---|---|
| PCIe Gen3 고정 | `setpci` 로 상위 포트 목표 속도 변경 → 링크 재협상 | 재부팅 |
| 코어 클럭 상한 | `sudo nvidia-smi -lgc 300,1600` | `-rgc` |
| 전력 제한 | `sudo nvidia-smi -pl 250` | `-pl 350` |

- 재부팅하면 모두 풀린다. 관리자 서비스 `nvidia-powerlimit` 가 부팅 때 350 W 를 건다 → 자동 복구 서비스가 그 뒤에 다시 건다
- 적용 확인: 부하 중 `pcie.link.gen.current` = 3 · `clocks.current.graphics` ≤ 1600 MHz

| 감시 | 30초마다 · `nvidia-smi` 2번 실패 AND Xid 79 → `sync` → sysrq `b` |

## 설정 원칙

- `ultralytics==8.4.102` — 노트북 기준선과 비교하려면 버전 고정
- torch 는 드라이버 CUDA 버전에 맞춘다
- `yolo` 명령은 PATH 에 없다 → conda 환경 안의 절대경로로 부른다
- JupyterLab 셀은 연결이 끊기면 죽는다 → 긴 작업은 백그라운드로. **재부팅되면 tmux 도 사라지므로** 긴 학습은 자동 복구 서비스의 이어 학습 대상으로 등록한다

- 재부팅 뒤 다운로드: rclone 은 같은 명령 재실행, gdown zip 은 `unzip -t` 확인
- 공개 저장소 — 커밋 전 민감 정보 검사 (키 · 내부 주소 · 이메일 주소)
