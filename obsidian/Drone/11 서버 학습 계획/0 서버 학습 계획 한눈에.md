> [!summary] 노트북 프로토타입 → **실기체에 올릴 사람 탐지 모델**을 학과 서버(RTX 3090)에서 학습한다
> 핵심 변화는 세 가지다.
> 1. 사람 크기를 **우리 카메라 기준(모델 입력 1280 에서 약 18~133 px)** 으로 다시 맞춘다
> 2. 데이터를 **촬영 각도로 분류**하고, 시험은 **장소가 다른 자체 촬영 영상**으로 한다
> 3. 설정을 한 파일(`hyp_v2`)로 고정하고 **하나씩만 바꿔** 비교한다

## 프로토타입과 무엇이 다른가

|           | 노트북 프로토타입                          | **서버 실기체용**                                            |
| --------- | ---------------------------------- | ------------------------------------------------------ |
| 목표 사람 크기  | 94 px 고정 (60° · 20 m · 키 1.7 m 가정) | **22~120 px 로그 균등** (54°/60.5° · 16~30 m · 하향 서 있음 포함) |
| 크기 지터     | × 0.75~1.35                        | 목표 분포 자체가 넓다 · 학습 중 `scale 0.3`                        |
| 시점        | 섞인 채 사용                            | **비행별 각도 태그** · 마운트에 맞춘 비율                             |
| 데이터       | NOMAD 30명 + WiSARD 10 비행           | NOMAD 60명 · WiSARD 전체 · **SARD** · 음성 · **자체 촬영**      |
| 누운 사람 비중  | 20.7%                              | **40%**                                                |
| 시작 가중치    | VisDrone yolov8s                   | **COCO yolo11s** (yolo26s · p2 · 11m 비교)               |
| 입력 크기     | 960                                | **1280**                                               |
| 회전 · 상하반전 | 10° · 0                            | **180° · 0.5** (90° 단위 방식과 비교)                         |
| 평가        | 통합 검증셋 · 겨울 시간 분할                  | **장소 분리 시험셋** · 크기 구간별 · 오탐/프레임                        |
| 배포        | `.pt`                              | **TensorRT FP16** · 4080 SUPER                         |

## 결정·확인이 필요한 것

> [!question] 사람이 정해야 진행되는 것
> - [ ] **마운트 각도** (90° / 60° / 45°) — 데이터 섞는 비율이 바뀐다 · 비전+비행
> - [ ] **렌즈 화각 실측** — 체커보드 · 렌즈 도착 즉시
> - [ ] **기체 첫 비행 날짜** — S7 시작점 · 서성훈
> - [ ] **촬영지 3곳 · 비행·촬영 허가** — 팀
> - [ ] **AI-Hub 182 신청** — 사용자 직접 → 표본 각도·고도 분석
