## 1단계 — 평가 · 선택 기준 바로잡기 (재학습 없음 · 싸다)

- [ ] **① 가시도 낮은 사람 무시 영역 처리** — 가시도 < 30 인 사람을 라벨에서 빼고 그 영역을 **회색(114)으로 칠한다** (VisDrone ignore region 방식). 학습 · 평가 둘 다. 가시도 구간별 AP 를 따로 보고
  - 라벨만 빼고 칠하지 않으면 모델이 찾았을 때 **오탐**으로 잡힌다 → 반드시 칠할 것
  - 정의를 문서에 밝히면 정당한 처리 (숫자 부풀리기 아님)
- [ ] **② best.pt 를 AP50 으로 고르기** — 지금은 mAP50-95 로만 고른다 (아래 ⚠). `train_person.py` 에 옵션으로
  ```python
  from ultralytics.utils import metrics
  metrics.Metric.fitness = lambda self: float(self.mean_results()[2])  # mAP50
  ```
- [ ] **③ 라벨 누락 검수** — 4-3절 모음판에 "라벨 없는 사람 같은 예측" 이 있었다 = **맞췄는데 오탐 처리.** conf 높은 오탐 상위 수백 개 모음판 → 누락 라벨 보충

> [!warning] fitness 공식이 문서와 다르다 (09-15 확인)
> 설치된 ultralytics 8.4.102 `utils/metrics.py:1007` 은 `w = [0, 0, 0, 1]` → **fitness = mAP50-95 만.**
> [[fitness와 조기 종료]] · `CLAUDE.md` §4-2 · SERVER_PROGRESS 4-3 의 `0.1·mAP50 + 0.9·mAP50-95` 는 옛 버전 공식이다. 파일은 09-10 설치 뒤 안 바뀌었으니 M1 · M2 도 mAP50-95 로 골라졌다 (best 22에폭은 두 공식이 같아 결과엔 영향 없음).

## AI-Hub 182 받기

### 확인한 사실 (09-15 · `aihubshell -mode l 182`)

| 항목 | 값 |
|---|---|
| 이름 | **064. 드론 이동체 인지 영상(도로 고정)** · 2020 구축 · 4K · 서비스 3종 (교차로 · 조난자 수색 · 드론택시) |
| 신청 | **내국인만** · 데이터 페이지에서 신청 → 승인 후 다운로드 |
| 조난자 라벨 | Training 39개 · Validation 6개 zip — **합계 약 0.3 GB** |
| 조난자 원천 | Training 39개 **815 GB** · Validation 6개 **121 GB** (zip 하나 9~30 GB) |
| 각도 · 고도 | JSON 에 `angle`(°) · `altitude`(m) 필드, 파일명도 `획득자_날짜_날씨_각도_고도_시간_프레임번호.jpg` |
| 서버 여유 | `/` 4.7 TB (09-15) |

> [!tip] 라벨만 먼저 받는다
> 원천 936 GB 를 받기 전에 **0.3 GB 라벨로 각도 · 고도 분포를 뽑아** 하향 60° 이상 · 고도 10~40 m 인 zip 만 고른다 ([[3 데이터 구성]] 7절).

### 1. 신청 · 키 (사용자 직접 · 브라우저)

1. <https://www.aihub.or.kr/aihubdata/data/view.do?dataSetSn=182> 로그인 → **다운로드(신청)** → 승인 완료 확인
2. AI-Hub 에서 **API 키 발급** (aihubshell 공식 안내: "회원가입 후 키를 발급")

### 2. 서버에 aihubshell 설치 · 목록 확인 (키 없이 됨)

```bash
mkdir -p ~/bin && curl -o ~/bin/aihubshell https://api.aihub.or.kr/api/aihubshell.do && chmod +x ~/bin/aihubshell
~/bin/aihubshell -mode l 182 | less      # 파일 목록 · 용량 · filekey
```

### 3. 키를 파일로 저장 (채팅 · 문서 · 셸 기록에 남기지 않는다)

```bash
mkdir -p ~/.config/aihub && (umask 077; read -rsp 'AI-Hub API key: ' K; echo; printf '%s' "$K" > ~/.config/aihub/api_key)
```

aihubshell 은 `-aihubapikey` 가 없으면 환경변수 `AIHUB_APIKEY` 를 쓴다 → 명령줄에 키를 안 쓴다.
(단 스크립트 안의 `curl -H "apikey:…"` 는 실행 중 `ps` 에 보인다 — 공용 서버 주의)

### 4. 조난자 라벨만 받기 (약 0.3 GB)

```bash
mkdir -p ~/JupyterLAB/Capstone/data/raw/AIHub182 && cd ~/JupyterLAB/Capstone/data/raw/AIHub182
# Training 라벨 39 + Validation 라벨 6
AIHUB_APIKEY=$(cat ~/.config/aihub/api_key) ~/bin/aihubshell -mode d -datasetkey 182 -filekey \
47992,47993,47994,47995,47996,47997,47998,47999,48000,48001,47983,47984,47985,47986,47987,47988,47989,47990,47991,47920,47921,47922,47923,47924,47925,47926,47927,47928,47929,47930,47931,47932,47933,47934,47935,47936,47937,47938,47939,47852,47853,47854,47855,47856,47857
```

- 현재 폴더에 `download.tar` 로 받아 풀고 `.part` 를 병합한 뒤 tar 를 지운다 → 안에 zip 이 남으니 `unzip` 한다
- `data/` 는 git 제외 (`Capstone/.gitignore`) — **AI-Hub 약관상 원본 · 파생물은 git 에 올리지 않는다**

### 5. 각도 · 고도 분포 → 원천 zip 고르기

라벨 JSON 의 `angle` · `altitude` 를 zip(촬영지)별로 집계 → 쓸 zip 결정 → 원천 filekey 는 `-mode l 182` 의 `원천데이터/03 survivor` 에서 확인.

### 6. 원천 받기 (고른 것만 · 한 개씩)

zip 하나가 9~30 GB 이고, aihubshell 은 **Ctrl+C 시 받던 tar 를 지운다** → 여러 개를 한 번에 걸지 말고 **하나씩 · 백그라운드로.** 받는 동안 tar + 해제본으로 파일 크기의 2~3배 공간이 필요하다.

```bash
cd ~/JupyterLAB/Capstone/data/raw/AIHub182
setsid nohup bash -c 'for k in <고른 filekey들>; do AIHUB_APIKEY=$(cat ~/.config/aihub/api_key) ~/bin/aihubshell -mode d -datasetkey 182 -filekey $k; done' \
  > ~/JupyterLAB/Capstone/drone_yolo/logs/aihub182_dl.log 2>&1 < /dev/null &
```
