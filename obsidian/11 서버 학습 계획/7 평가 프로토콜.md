## 1. 시험셋 (`test_v2/`)

| 시험셋 | 내용 | 무엇을 보나 | 비고 |
|---|---|---|---|
| `nomad_holdout10` | 배우 004·008·014·018·048·059·071·079·088·094 | 여름 농장 · 누운 사람 · 노트북 모델과 **공정 비교** | 024·028 은 stage1_all 학습 배우라 제외 → [[NOMAD 검증 배우 불일치]] |
| `wisard_nadir` | 학습에 안 쓴 **하향 비행** | 산지 · 가을/겨울 · **하향 시점** | 비행 태그로 선별 → [[3 데이터 구성]] |
| `okutama_90` | Okutama **90° 영상**만 1920×1080 축소 | 미학습 도메인 · 하향 · Lying 라벨 | 노트북 → 서버 복사 필요 (9.6 GB) |

| `negatives_test` | 사람 없는 영상 (WiSARD 음성 비행 · 자체 촬영) | **오탐 / 프레임** (NFR-V06) | 학습 음성과 겹치지 않게 |
| **`own_siteC`** | 자체 촬영 **촬영지 C 전체** | **최종 판정** — 우리 카메라 · 한국 · 장소 분리 | 촬영 후 추가. 그 전에는 `wisard_nadir`+`okutama_90` 이 대리 |

> [!warning] 학습 중 best.pt 를 고르는 **검증셋**(`val`)과 최종 판정하는 **시험셋**(`test_v2`)은 다르다
> 검증셋으로 판정하면 그 검증셋에 맞춘 모델이 뽑힌다.

| 지표 | 정의 | 설정 | 요구명세서 |
|---|---|---|---|

| AP50-95 | IoU 0.50~0.95 평균 | 참고 | |

| 정밀도 @0.15 | | | |
| **F2 최대값 · 그때의 신뢰도** | → [[신뢰도 임계값과 F2]] | | NFR-V05 |
| **오탐/프레임 @0.15** | `negatives_test` 의 박스 수 ÷ 장수 | | NFR-V06 (≤1) |
| **크기 구간별 발견율** | 사람 박스 긴 변(모델 입력 px) 구간별 재현율 | IoU **0.3**, 신뢰도 0.15 | 고도 한계 판단 |
| 자세별 재현율 | 누움 / 서 있음·걷기 / 앉음 | NOMAD 활동 · SARD · Okutama 라벨 | 과제 핵심 |

| **추론 시간** | 1920×1080 한 장 · 전처리+추론+후처리 · 평균 / P95 | 3090 · 4080 SUPER | NFR-V01 (≤30 ms) |

> [!note] 크기 구간별 발견율은 왜 IoU 0.3 인가
> 20 px 사람은 박스가 3~4 px 만 밀려도 IoU 0.5 아래로 떨어진다. 위치 신고에는 영향이 없는 차이다 → [[IoU]].
> 요구명세서 수치(AP50)는 0.5 로, "찾았나"를 보는 크기 분석은 0.3 으로 잰다.

## 3. 입력 크기

- 기본 평가는 **운용 입력 1280** (`imgsz=1280`, 1920×1080 을 비율 유지 축소)
- 최종 후보 2개는 **1600 · 1920** 입력으로도 재서 "추론만 크게" 의 이득을 본다
- 학습 입력과 평가 입력이 다르면 표에 **반드시 둘 다** 적는다

## 4. 판정 규칙 (실험 전에 고정)

```
1) 오탐/프레임 @운용신뢰도 ≤ 1.0                     ← 못 넘으면 탈락
2) 하향 시험셋(own_siteC, 없으면 wisard_nadir+okutama_90) 에서
   16~64 px 구간 발견율 평균이 가장 높은 모델            ← 1순위
3) 차이가 0.01 미만이면 → nomad_holdout10 사람 AP50     ← 2순위
4) 그래도 비슷하면 → 더 빠른 모델
```

- **차이가 0.01 미만이면 "같다"** 로 본다. 꼭 가려야 하면 `seed` 를 바꿔 한 번 더 돌린다
- 통합 검증셋(`combined`) 수치로 판정하지 않는다
- 소표본(70장 등)으로 결론 내지 않는다 → [[함정 모음]]

## 5. 실행과 기록

새 스크립트 `eval_v2.py` — 기존 `eval_domain.py` · `eval_scale.py` · `eval_pose3.py` 를 합친다.

```bash
python eval_v2.py --imgsz 1280 --conf 0.15 --iou-find 0.3 \
  --sets nomad_holdout10 wisard_nadir okutama_90 sard_test negatives_test \
  --weights weights/yolov8s_stage1_all.pt runs_person/<후보들>/weights/best.pt
```

출력 `metrics/eval_v2.csv` 한 줄 = 모델 × 시험셋

| 열 |
|---|
| model · train_imgsz · eval_imgsz · set · images · persons |
| ap50 · ap50_95 · recall@c · precision@c · f2_max · f2_conf |
| fp_per_frame@c |
| find_16_24 · find_24_40 · find_40_64 · find_64_100 · find_100_140 |
| find_lying · find_standing · find_sitting |
| find_vis_low · find_vis_mid · find_vis_high |

### 눈으로 보는 검사 — 빼먹지 말 것

## ⚠ 장소 분리 구멍 (2026-09-18 확인)

[[NFR-V03 탐지 정확도]] 는 "**학습/평가 장소 분리**에서 AP50 ≥0.80" 인데, **지금 어느 시험셋도 이 조건을 만족하지 못한다.**

WiSARD 크롭 파일명을 세어 본 결과 — val 장소 6곳이 **전부 train 에도 있다**:

| | 장소별 크롭 수 |
|---|---|
| train | SkookumCreek 5,110 · Carnation 4,942 · Karen 3,338 · Airfield 1,586 · Bellingham 1,446 · SuddenValley 1,388 · Mission 448 · Everson 436 · MtErie 414 · FHL 202 |
| val | FHL 1,618 · MtErie 852 · SuddenValley 642 · Everson 512 · Mission 218 · Airfield 206 |

비행 단위로만 나눴다. NOMAD 는 배우 단위이고 촬영지가 하나다. 어제 만든 판정용 `det_fov_test_budget` 도 같은 val 비행에서 나왔으니 똑같이 장소가 섞여 있다.

→ **지금 숫자는 NFR-V03 기준으로 낙관적이다.** 모델 · 화각 사이 **상대 비교**엔 문제가 없지만 "AP50 0.80 달성" 을 말할 근거는 아니다.
