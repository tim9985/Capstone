> [!summary] 학습 이미지 속 사람 크기를 **우리 카메라에 찍힐 크기 분포**에 맞춘다
> 프로토타입: 사람을 **94 px ± 지터(70~127 px)** 로 맞췄다 → 실제 운용의 **작은 사람(40 px 미만)이 학습 데이터에 1%** 뿐이었다.
> 제안: 목표 크기를 **22~120 px 로그 균등**으로 뽑고 학습 중 `scale 0.3` → 운용 분포와 거의 같아진다.

## 1. 왜 크기를 맞추나

- NOMAD 원본은 5472×3078 이고 사람이 거리에 따라 **27~233 px** 로 제각각이다
- 그대로 넣으면 모델은 **데이터에 흔한 크기만** 잘 찾는다
- 모델은 "몇 px 짜리 사람"을 배운다 → 학습 분포가 운용 분포와 달라지면 그 구간에서 무너진다
  (프로토타입은 24 px 에서 여름 재현율 0.39 로 **절벽**이 있었다 → [[탐지 4 - 고도·해상도 평가]])

## 2. 지터란

**지터(jitter)** = 값을 매번 조금씩 무작위로 흔드는 것.

| 지터 | 하는 일 | 설정 위치 |
|---|---|---|
| **크기 지터** | 원본마다 사람 목표 크기를 무작위로 뽑아 확대·축소 | 전처리 (`nomad_prep.py` 의 `SCALE_JITTER`) |
| 위치 지터 | 크롭 창을 사람 중심에서 무작위로 밀어 사람이 늘 가운데 오지 않게 | 전처리 (±30%) |
| 학습 중 크기 증강 | 매 배치마다 이미지를 `1 ± scale` 배로 다시 확대·축소 | 학습 인자 `scale` |

> [!important] 최종 크기 = 전처리 크기 × 학습 중 `scale` 배율
> 둘을 **따로 정하면 안 된다**. 프로토타입은 전처리 70~127 px 에 `scale 0.5`(0.5~1.5배)가 곱해져 실제로는 **50~159 px** 을 배웠다.

## 3. 프로토타입 설정이 틀린 이유

`TARGET_PERSON_PX = 94` 는 "고도 20 m · **화각 60°** · 1280 px · **키 1.7 m**" 가정에서 나왔다.

| 가정 | 실제 |
|---|---|
| 화각 60° | 60° 는 **대각** 화각. 수평은 **54°** |
| 사람 = 키 1.7 m 가 다 보임 | 하향 90° 에서 서 있는 사람은 **어깨 0.5 m** 만 보인다 |
| 고도 20 m 하나 | 운용 **16~30 m** |

→ [[1 기준 조건 - 카메라·화각·마운트]] 의 표로 다시 계산하면 모델 입력 1280 기준 **약 18~133 px**.

## 4. 방식별 최종 크기 분포 (모의 계산 40만 개)

최종 크기 = 전처리 목표 × 학습 중 `scale` 배율. 비율은 사람 인스턴스 기준.

| 방식 | 16~24 | 24~40 | 40~64 | 64~100 | 100~140 | 140+ | 5~95% 범위 |
|---|---:|---:|---:|---:|---:|---:|---:|
| A 현재: 94 × U(0.75, 1.35), scale 0.5 | 0% | **1%** | 16% | 37% | 33% | 13% | 50~159 px |
| B 09-12 메모안: 94 × U(0.65, 1.45), scale 0.5 | 0% | 2% | 17% | 38% | 29% | 15% | 47~167 px |
| **C 제안: 로그 균등 22~120, scale 0.3** | **8%** | **28%** | 28% | 25% | 10% | 1% | **22~116 px** |
| D 로그 균등 22~120, scale 0.5 | 10% | 26% | 28% | 22% | 10% | 3% | 19~126 px |
| **운용 목표** (하향 90° · 16~30 m · 서기/누움 반반 · 54°/60.5°) | 2% | **28%** | 22% | 35% | 13% | 0% | 26~113 px |

> [!success] C 가 운용 분포와 가장 비슷하다
> A·B 는 **24~40 px (고도 16~30 m 서 있는 사람)** 이 1~2% 뿐이다.
> B 는 **누운 사람만** 보면 맞는 범위다 (09-12 메모의 표는 누운 사람 기준 → [[9.12 마운트각에 따른 고려]]). 서 있는 사람까지 찾으려면 아래쪽을 넓혀야 한다.

### 왜 로그 균등인가
- 균등 분포(22~120 에서 아무 값)면 **큰 쪽**이 많이 뽑힌다 (60~120 이 전체의 60%)
- 로그 균등은 **배율 구간마다 같은 양** — 22→44, 44→88, 88→120 이 고르게 나온다
- 작은 물체는 원래 더 어렵기 때문에 **작은 쪽에 충분한 표본**이 필요하다

```python
target_px = math.exp(random.uniform(math.log(22), math.log(120)))
```

## 5. 제안 설정 (C)

| 항목 | 프로토타입 | **실기체용** | 이유 |
|---|---|---|---|
| 기준 | 사람 박스 긴 변 | 사람 박스 긴 변 | 유지 |
| 목표 크기 | 94 px 고정 | **22~120 px 로그 균등** | 4절 |
| 크기 지터 | × U(0.75, 1.35) | (목표 분포에 포함) | |
| 학습 중 `scale` | 0.5 | **0.3** | 전처리 분포를 너무 흐리지 않게 |
| 크롭 창 | 1280×720 | 1280×720 | 모델 입력 1280 에서 1:1 → 크롭 px = 모델 입력 px |
| 위치 지터 | ±30% | ±30% | 유지 |
| 최대 확대 | 2.2배 | 2.2배 | 넘으면 화질이 무너진다 |
| 경계에 잘린 사람 | 면적 40% 미만이면 라벨 제외 | 유지 | |
| 최소 박스 | 8 px | 8 px | |
| NOMAD 거리 | 10 · 30 m | **10 · 30 · 50 (+70) m** | 작은 목표는 먼 거리 원본에서 |
| 기록 | 사분위수 | **목표 px · 실제 px · 배율 · 확대 여부 전부** | 분포 검증 |

### 원본마다 도달 가능한 크기가 다르다

1280×720 창을 채우려면 원본을 **일정 배율 이상**으로 줄일 수 없다.

| 원본 | 창을 채우는 최소 배율 | 사람 중앙값 | **만들 수 있는 최소 크기** | 배정할 목표 |
|---|---:|---:|---:|---|
| NOMAD 10 m | 0.234 | 233 px | **약 55 px** | 55~120 px |
| NOMAD 30 m | 0.234 | 78 px | 약 18 px | 22~120 px |
| NOMAD 50 m | 0.234 | 47 px | 약 11 px | 22~60 px (확대 없이) |
| WiSARD (1920×1080) | 0.667 | 작음 | 원본의 2/3 | 원본 크기 × 0.67~2.2 안에서 |
| SARD | 해상도 확인 후 | | | |

- 뽑은 목표가 도달 불가능하면 **다시 뽑는다** (억지로 맞추면 분포가 한쪽으로 쏠린다)
- 프로토타입에서 확대 2.2배 초과로 버린 **WiSARD 2,663장**은 목표가 작아지면 대부분 살아난다

## 6. 화질 열화 — 우리 카메라 영상처럼

공개 데이터는 좋은 카메라로 찍은 선명한 영상이다. 우리는 **짐벌 없는 기체 · 1/2.8" 센서 · H.264 무선 전송**이다.

| 열화 | 범위 (초안) | 확률 | 흉내 내는 것 |
|---|---|---:|---|
| JPEG 재압축 | 품질 35~85 | 0.3 | H.264 압축 블록 |
| 이동 흐림 | 커널 3~7 px, 방향 무작위 | 0.15 | 진동 · 전진 비행 |
| 가우시안 노이즈 | σ 2~8 | 0.2 | 작은 센서 · 흐린 날 |
| 축소 후 확대 | × 0.5~0.9 | 0.15 | 렌즈·전송 해상도 저하 |

- ultralytics 8.4.102 에는 사용자 증강 인자가 없다 → **전처리에서 크롭을 저장할 때** 적용 (시드 고정)
- 범위는 초안이다. **첫 실제 영상**을 받으면 선명도(라플라시안 분산)·블록 정도를 재서 맞춘다
- 켜고 끄는 효과는 실험 S6 에서 본다 → [[6 실험 순서와 판정]]

## 7. 명령 (구현할 옵션)

```bash
# NOMAD — 새 옵션: --target-dist, --target-min/max, --lying-ratio, --degrade, --negatives
python nomad_prep.py --out data/det_v2/nomad \
  --distances 10,30,50,70 --per-image 1 \
  --target-dist loguniform --target-min 22 --target-max 120 \
  --lying-ratio 0.40 --negatives 0.05 --degrade 0.3

# WiSARD — 새 옵션: --tags, --views
python wisard_prep.py --out data/det_v2/wisard \
  --tags configs/wisard_flight_tags.csv --views nadir,tilted,oblique,side --exclude-light night \
  --target-dist loguniform --target-min 22 --target-max 120 --degrade 0.3

python make_configs.py            # 절대경로 yaml 재생성
python dataset_stats.py --data data/det_v2   # 분포 확인
```

## 데이터셋별 라벨을 우리 규격으로 (실제 구현)

원본은 형식이 제각각이라 **형식 통일 → 크기 맞추기 → 크롭 → 분할** 순서로 다시 만든다.

| 데이터 | 원본 라벨 | 변환 스크립트 | 분할 단위 |
|---|---|---|---|
| NOMAD | `annotations.json` 절대 픽셀 `[x,y,w,h]` + 가시도 | `nomad_prep.py` | 배우 |
| WiSARD | 이미지마다 `.txt` (이미 YOLO) | `wisard_prep.py` | 비행 (월별 층화 · 비행 1개뿐인 달은 시간 분할) |
| SARD | Roboflow yolov8 `.txt` (6클래스) | 하드링크 + 클래스 0 치환 | (재분할 필요 — 연속 프레임 누수) |
| AI-Hub 182 | 프레임마다 JSON · **4점 폴리곤** + 자세 · 고도 | `aihub_prep.py` (예정) | **장소** |

```
원본 이미지 + 라벨
 ① 형식 통일   폴리곤 · 절대좌표 → YOLO (class cx cy w h, 0~1) · 클래스 전부 person=0
 ② 크기 맞추기  사람 긴 변이 목표 px 가 되도록 이미지 배율 조정
                --target-dist loguniform --target-min 16 --target-max 160   (기본값은 옛 방식 94 px × 지터)
                도달 가능 범위 = [원본 사람 × 창 채우는 최소 배율, 원본 사람 × 2.2] 와 목표 범위의 교집합
 ③ 크롭        1280×720 창 · 위치 지터 ±30 % · 창 밖 60 % 넘게 나간 사람은 라벨에서 제외
 ④ 음성 섞기    사람 없는 프레임 일부 (`--negatives`, WiSARD 10 %)
 ⑤ 분할        배우 · 비행 · 장소 단위 (프레임 단위로 섞으면 점수가 부풀려진다)
→ data/det_fov/<이름>/{images,labels}/{train,val} + data.yaml → configs/data_fov.yaml 로 묶어 학습
```

평가용 시험셋은 같은 원리로 **칸마다 목표 크기를 고정**해서 만든다 (`make_fov_testsets.py` · 1920×1080 판은 `make_fullframe_testset.py`) → [[화각·고도 비교 실험]]
