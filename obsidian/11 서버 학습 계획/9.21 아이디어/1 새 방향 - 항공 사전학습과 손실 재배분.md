# 방향 1 — 항공 사전학습

## 발단

NOMAD 원논문 저자가 성능 저하의 1순위 원인으로
*"training data bias toward **ground views rather than aerial ones**"* 를 지목했다.
확인해 보니 **우리가 정확히 그 상태였다.**

| 학습 | 시작 가중치 |
|---|---|
| `fov_11m_1280_all` | `yolo11m.pt` (COCO) |
| `l1_11l_1280` | `yolo11l.pt` (COCO) |
| `v3a_11m_neg` (진행 중) | `yolo11m.pt` (COCO) |

> [!warning] 의식적인 결정이 아니었다
> 노트북 계보는 **공개 YOLOv8s-VisDrone → NOMAD+WiSARD → stage1_all** 로 항공 시점을 한 번 거쳤다 (`WEIGHTS.md`).
> 서버에서 YOLO11 로 바꾸며 **YOLO11용 VisDrone 가중치가 없어** COCO 에서 직접 출발하게 됐다.
> **아키텍처 교체의 부산물**이지 판단의 결과가 아니다.
> 그래서 "항공 사전학습을 잃은 손해" 를 **분리해서 잰 적이 없다.**

## 공개 가중치를 전수 조사했다 (HuggingFace `dronefreak` 100개)

직접 학습할 필요가 없었다 — **YOLO11 전 크기 VisDrone 가중치가 이미 공개돼 있다.**

모델 카드는 **0~100 스케일**로 적혀 있다. 우리 표기(0~1)로 환산해 같이 적는다.

| 모델 | imgsz | 에폭 | VisDrone val<br>mAP50 (0~1) | mAP50-95 (0~1) |
|---|---:|---:|---:|---:|
| yolov9e | 640 | 300 | **0.4002** | **0.2373** |
| yolov11x | 640 | 300 | 0.3844 | 0.2260 |
| yolov26x | 640 | 300 | 0.3833 | 0.2248 |
| rfdetr-medium | — | — | 0.3682 | 0.2014 |
| yolov8x | 640 | 300 | 0.3681 | 0.2152 |
| yolov26m | 640 | 300 | 0.3667 | 0.2122 |
| **yolov11m** ← 우리 아키텍처 | 640 | 300 | **0.3635** | 0.2102 |

라이선스 AGPL-3.0 (ultralytics 와 동일) · `best.pt` · `args.yaml` 공개.

> [!warning] 이 숫자를 우리 val mAP50 0.4779 와 나란히 놓지 말 것
> · **데이터가 다르다** — VisDrone 은 도시 교통 장면, 우리는 농지·수풀
> · **클래스 수가 다르다** — VisDrone 은 10클래스라 **m**AP 가 클래스 평균이고,
>   보행자보다 훨씬 쉬운 car·bus 가 섞여 평균을 올린다. 우리는 1클래스
> · **입력이 다르다** — 640 vs 1280
>
> VisDrone 에서 0.3635 가 우리 0.4779 보다 낮다고 "우리가 더 잘한다" 가 아니다.
> 이 표는 **어느 사전학습 가중치를 고를까**에만 쓴다.

> [!info] "COCO 안 거친" 모델은 사실상 없고, 있어도 우리에게 더 나쁘다
> 위 가중치들의 `args.yaml` 은 전부 `model: yolo11m.pt` · `pretrained: true` — **COCO → VisDrone** 이다.
>
> | | 장수 |
> |---|---:|
> | COCO | 118,000 |
> | VisDrone train | **6,471** (COCO 의 1/18) |
>
> 이 규모로 처음부터 백본을 학습하면 저수준 특징(모서리·질감)조차 안 잡힌다.
> 이 분야 표준이 `COCO → 항공 → 목표` 인 이유다.
> **NOMAD 저자의 지적은 "COCO 를 쓰지 마라" 가 아니라 "COCO 에서 바로 오지 마라" 다.**

> [!note] 원격탐사 기반모델(SatMAE · Scale-MAE · RVSA · MTP)은 우리 용도가 아니다
> 위성 수직 하향 · GSD 미터 단위(우리는 드론 30 m · GSD 1~2 cm) · 대상이 건물·차량·선박 ·
> ViT 백본이라 YOLO11 에 못 붙인다. DOTA 사전학습 OBB(`yolo11m-obb.pt`)도 클래스에 사람이 없다.

## imgsz 640 이 걸리는가 — **해상도는 아니고, 객체 크기가 문제다**

동물원 25종이 **전부 640** 이다. 1280 이상은 **TPH-YOLOv5**(VisDrone 2021 챌린지 4위 · imgsz 1536) 하나뿐인데,
YOLOv5l 에 트랜스포머 헤드를 붙인 개조라 우리 파이프라인(`eval_tile.py` · TensorRT · ultralytics 8.4.102 고정)이 못 쓴다.

### 문헌은 "저해상도 사전학습 → 고해상도 미세조정" 을 **권장**한다

| 근거 | 내용 |
|---|---|
| **FixRes** (NeurIPS 2019) | 논문 주장이 정확히 이것이다. ResNet-50 을 224 로 학습 후 320 용으로 미세조정 → ImageNet top-1 **0.798**. **처음부터 320 으로 학습한 것보다 높다.** 학습 때 `RandomResizedCrop` 이 객체를 확대해 보여줘 **겉보기 크기가 추론 때보다 크고**, 고해상도 미세조정이 그 불일치를 교정한다 |
| **YOLOv5 P5/P6** | P5 는 640, P6 는 **1280** 으로 학습한다. 커스텀 데이터셋을 640 가중치에서 1280 으로 미세조정하는 건 **일상적 관행** |
| ultralytics 미세조정 가이드 | *"작은 객체가 있는 데이터셋은 `imgsz=1280` 이 디테일을 보존하고, 640 대신 1280 을 쓰면 더 작은 객체를 잡아 mAP 가 오른다"* |
| **우리 실측** | 지금 모든 모델이 COCO 640 → 우리 1280 인데 무너지지 않았다 (val mAP50 0.478). 추론 해상도를 1280 → 1920 으로 올렸을 때도 **+6.1 %p(상대 +21.6 %)** 올랐다 |

> [!success] "고해상도 전이가 성능을 떨어뜨린다" 는 걱정은 기각
> 해상도 숫자 자체는 문제가 아니다. YOLO 는 완전 합성곱이라 가중치가 입력 크기와 무관하다.

### 진짜 위험은 **크기(scale) 불일치** 다

TinyPerson 계열 연구가 이걸 `Scale Match` 로 다룬다 —
*"사전학습 데이터와 검출기 학습 데이터 사이의 **scale mismatch** 가 성능 저하를 부른다."*
SNIP 도 *"학습하지 않은 해상도에서 시험하는 것은 차선"* 이라 하는데,
정확히는 **학습하지 않은 객체 px 크기**가 문제다.

우리 데이터로 실측하면 (VisDrone train 사람 106,396개 · 원본 8열 주석):

| | 사람 긴 변 px (분위수 5/50/95) |
|---|---|
| VisDrone **원본 배율** | 9 / **24** / 69 |
| VisDrone **@ imgsz 640** (1400×1050 → ×0.457) | 4 / **11** / 32 |
| **우리 @ 1280** (1:1 배율) | 16 / **~50** / 160 |

**중앙값 11 px vs 50 px — 4.5배 차이다.** 11 px 는 stride 8 격자에서 1.4칸,
50 px 는 6.3칸이라 **활성화하는 FPN 층 자체가 다르다** → 개념정리 C절 (`Capstone/05_드론사람탐지_개념정리.html` · 볼트 밖)

> [!important] 그래서 A·B 두 안이 바로 이 가설을 가른다
> · **A** — 공개 640 가중치 (사전학습 객체 **11 px**) → 우리 1280
> · **B** — 우리가 **1280 으로** VisDrone 사전학습 (객체 **24 px**) → 우리 1280
>
> **B 안이 곧 Scale Match 를 하는 것**이다. A 가 무효면 B 로 "크기 불일치가 원인이었나" 를 가린다.
> 다만 B 의 사전학습은 30에폭이라 A(300에폭)와 에폭이 10배 차이난다 — 그 교란은 남는다.

출처: FixRes arXiv 1906.06423 · SNIP arXiv 1711.08189 · TinyDet/Scale Match arXiv 2304.03428 ·
YOLOv5 v5.0 릴리스 노트 · Ultralytics Fine-tuning Guide

## 후보와 순서

세 후보 모두 **기준선 `fov_11m_1280_all` 과 사전학습만 다르게** 맞춘다.
고정할 것: `--imgsz 1280 --batch 8 --epochs 30 --optimizer SGD --lr0 0.01 --scale 0.3
--translate 0.15 --close-mosaic 0 --patience 100 --data configs/data_fov.yaml`

| | 시작 가중치 | 무엇을 가리나 | 준비 | 학습 |
|---|---|---|---|---|
| **A** | `dronefreak/visdrone-yolov11m` (640·300ep) | 항공 사전학습이 듣는가 | **5분** (내려받기 40.5 MB) | 13 h |
| **B** | 우리가 1280 으로 VisDrone 직접 학습 | A 가 무효면 **해상도 탓인가** | 3 h | 13 h |
| C | `visdrone-yolov9e` (VisDrone 최강) | 아키텍처를 바꿀 값어치가 있나 | 5분 | 13 h + 재검증 |

### A — 공개 가중치 (가장 먼저 · 이것만 해도 결론이 날 수 있다)

```bash
# ① 내려받기 — huggingface_hub 패키지가 없으므로 직접 받는다 (40.5 MB)
mkdir -p weights/visdrone_11m
curl -L -o weights/visdrone_11m/best.pt \
  https://huggingface.co/dronefreak/visdrone-yolov11m/resolve/main/best.pt

# ② 학습
python train_person.py --stage 1 --data configs/data_fov.yaml \
  --weights weights/visdrone_11m/best.pt \
  --imgsz 1280 --batch 8 --epochs 30 --patience 100 --close-mosaic 0 \
  --optimizer SGD --lr0 0.01 --scale 0.3 --translate 0.15 \
  --name vd_11m
```

> [!note] 클래스 수가 다르다 (VisDrone 10 → 우리 1)
> ultralytics 가 헤드를 **자동 재초기화**한다. 가져오는 것은 백본·넥이고,
> 이게 바로 우리가 원하는 부분이다(항공 시점 특징). 헤드는 어차피 처음부터 배운다.
> 다만 **첫 1~2 에폭은 헤드가 난수라 손실이 크게 튄다** — warmup 하락과 겹쳐 보이니 끊지 말 것.

**평가** (학습 후 순서대로)

```bash
python eval_fov.py     --weights runs_person/vd_11m/weights/best.pt --tag fovbudget   # 가림 40칸
python eval_tile.py    --weights runs_person/vd_11m/weights/best.pt                   # 타일 38/128 px
python eval_visibility.py --weights runs_person/vd_11m/weights/best.pt                # vis 구간별
```

### B — 1280 으로 직접 사전학습 (A 가 무효일 때만)

A 가 기준선과 같거나 나쁘면 두 가지 해석이 가능하다:
**(ㄱ) 항공 사전학습이 안 듣는다** / **(ㄴ) 640 → 1280 해상도 불일치 때문이다.**
B 는 이 둘을 가른다. **A 가 이기면 B 는 하지 않는다.**

```bash
# ① VisDrone 사전학습 — 자동 다운로드(약 2 GB) · train 6,471장이라 30에폭 ≈ 3 h
yolo detect train data=VisDrone.yaml model=yolo11m.pt imgsz=1280 \
  epochs=30 batch=8 optimizer=SGD lr0=0.01 close_mosaic=0 \
  project=runs_person name=pre_visdrone_11m

# ② 우리 데이터 — A 와 ①번 가중치만 다르다
python train_person.py --stage 1 --data configs/data_fov.yaml \
  --weights runs_person/pre_visdrone_11m/weights/best.pt \
  --imgsz 1280 --batch 8 --epochs 30 --patience 100 --close-mosaic 0 \
  --optimizer SGD --lr0 0.01 --scale 0.3 --translate 0.15 \
  --name vd1280_11m
```

⚠ B 의 사전학습은 30에폭이라 A 가 쓰는 공개 가중치(300에폭)보다 **덜 익었다.**
B 가 A 보다 나빠도 "해상도가 원인이 아니다" 라고 단정할 수 없다 — 에폭 차이가 교란이다.
그래서 **B 는 A 가 무효일 때의 원인 분해용**이지 A 와 우열을 가리는 실험이 아니다.

### C — 아키텍처 교체 (지금은 하지 않는다)

`visdrone-yolov9e` 가 VisDrone 에서 가장 강하지만(mAP50 0.4002 vs 11m 0.3635) 바꾸면:
NFR-V01 추론 시간 · TensorRT 엔진 · 타일 구성 · F2 임계값을 **전부 다시 재야 한다.**
게다가 우리는 이미 **모델 확대가 손해**였다 (11m → 11l 운용 구간 **상대 −3~−8 %**).
A·B 가 둘 다 무효이고 다른 축도 막혔을 때 꺼낼 카드다.

## 선행 확인 두 가지 (본 실험 전 · GPU 20분)

학습 13시간을 걸기 전에 먼저 재 둔다. 결과에 따라 A 를 할지 말지가 갈린다.

| | 무엇 | 읽는 법 |
|---|---|---|

②는 10클래스 모델이므로 **pedestrian·people 클래스만 골라** 채점해야 한다.

# 방향 2 — 손실 가중치 재배분

`box 7.5 / cls 0.5 / dfl 1.5` 는 ultralytics 기본값이고 **COCO 80클래스·큰 객체** 기준으로 맞춰진 값이다.
우리는 1클래스 · 초소형 · 배경 혼동이 전부다. 같은 배분이 맞을 이유가 없다.

## 우리가 잰 것

가림 지형 시험셋 · 각 칸 40장 · **가중치 적용 후**

| 대상 크기 | box | cls | dfl | 합 |
|---|---:|---:|---:|---:|
| 18 px | 3.755 | **5.174** | 1.868 | 10.798 |
| 34 px | 3.156 | 4.090 | 1.896 | 9.142 |
| 71 px | 2.340 | 3.361 | 1.913 | 7.614 |
| 106 px | 2.236 | 2.395 | 1.724 | 6.356 |
| **106 → 18 증가 (상대)** | +68 % | **+116 %** | +8 % | +70 % |

가중치를 걷어내면 18 px 에서 **raw cls = 10.35** · raw box = 0.50 · raw dfl = 1.25.
`cls` 0.5 가 큰 값을 눌러 놓고 `box` 7.5 가 작은 값을 키워 놓은 구조다.

> [!warning] "손실이 크니 가중치를 올려라" 는 자동으로 성립하지 않는다
> 손실이 크다는 건 **줄일 수 없는 항**이라는 뜻일 수도 있다.
>
> **진짜 근거는 실패 양상이다** — 정밀도@0.15 **0.685** / 재현율@0.15 **0.391**.
> 오탐이 넘치는 게 아니라 **진짜 사람에게 낮은 점수를 주고 있다.** 분류 문제지 위치 문제가 아니다.

문헌 근거: Psych-Occlusion 은 모델·데이터를 안 건드리고 **손실만 바꿔** 가림 성능을 올렸다.
사람이 수색할 때 박스를 맞추려 하지 않고 **위치만 본다**는 시각심리 실험을 반영해 중심 좌표를 우선했다.
우리도 같다 — **운영자가 스냅샷으로 판단**(UC-0705)하고 채점이 **IoU 0.5** 라 박스 정밀도의 운용 가치가 낮다.

## 후보와 순서

기준선 `fov_11m_1280_all` 과 **손실 가중치만** 다르게 맞춘다. 시작 가중치는 COCO `yolo11m.pt` 로 고정
(항공 사전학습은 방향 1 의 변수라 여기서 같이 바꾸지 않는다).

| | box | cls | dfl | 무엇을 가리나 | 학습 |
|---|---:|---:|---:|---|---|
| 기준선 | 7.5 | 0.5 | 1.5 | ultralytics 기본 (COCO 80클래스 기준) | — |
| **A (보수)** | 7.5 | **1.0** | 1.5 | 분류에 힘을 더 주면 미탐이 주는가 | 13 h |
| B (재균형) | **5.0** | **1.0** | 1.5 | 박스 정밀도를 포기하면 더 얻는가 | 13 h |

**A 부터.** B 는 두 개를 같이 바꿔 원인이 안 갈린다.
A 가 들으면 B 로 더 밀고, A 가 무효면 **B 도 안 할 근거**가 된다 (cls 를 올려도 안 되면 box 를 낮춰도 안 된다).

### 0단계 — `train_person.py` 에 옵션 추가 (10분)

지금은 손실 가중치가 노출돼 있지 않다. `--translate` 때와 같은 방식으로 세 개를 뺀다.

```python
ap.add_argument("--box", type=float, default=7.5)
ap.add_argument("--cls", type=float, default=0.5)
ap.add_argument("--dfl", type=float, default=1.5)
# model.train(...) 호출에 box=args.box, cls=args.cls, dfl=args.dfl 추가
```

⚠ 기본값을 현재 값과 **똑같이** 둔다. 옵션을 추가하는 것만으로 기존 실험이 달라지면 안 된다.

### A — cls 0.5 → 1.0

```bash
python train_person.py --stage 1 --data configs/data_fov.yaml --weights yolo11m.pt \
  --imgsz 1280 --batch 8 --epochs 30 --patience 100 --close-mosaic 0 \
  --optimizer SGD --lr0 0.01 --scale 0.3 --translate 0.15 \
  --cls 1.0 \
  --name loss_a_11m
```

### B — box 7.5 → 5.0 · cls 0.5 → 1.0 (A 가 들었을 때만)

```bash
python train_person.py --stage 1 --data configs/data_fov.yaml --weights yolo11m.pt \
  --imgsz 1280 --batch 8 --epochs 30 --patience 100 --close-mosaic 0 \
  --optimizer SGD --lr0 0.01 --scale 0.3 --translate 0.15 \
  --box 5.0 --cls 1.0 \
  --name loss_b_11m
```

> [!danger] `best.pt` 선정과 충돌한다 — **B 에서 특히**
> `fitness = mAP50-95` 라 **박스가 빡빡해야 점수가 나온다** (8.4.102 · `w=[0,0,0,1]`).
> box 를 낮추면 mAP50-95 는 떨어지는데 AP50·재현율은 오를 수 있고, **엉뚱한 에폭이 best.pt 로 뽑힌다.**
> · 대응: **`best.pt` 와 `last.pt` 를 둘 다 평가**한다 (평가가 2배로 늘지만 30분이면 된다)
> · fitness 자체를 mAP50 으로 바꾸는 건 **별도 변수**라 같이 건드리지 않는다 → [[fitness와 조기 종료]]

### 평가 (A·B 공통 · `best.pt` 와 `last.pt` 각각)

```bash
for w in best last; do
  python eval_fov.py --weights runs_person/loss_a_11m/weights/$w.pt --tag fovbudget
  python eval_visibility.py --weights runs_person/loss_a_11m/weights/$w.pt
  python eval_tile.py --weights runs_person/loss_a_11m/weights/$w.pt
done
```

**가장 먼저 볼 칸은 `vis 0~30 재현율@0.15` (기준선 0.286)** 이다 — 이게 이 실험의 본래 목표다.
전체 평균만 보면 가림 구간의 변화가 묻힌다.
