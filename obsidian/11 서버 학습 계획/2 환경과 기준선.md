## 2. 소프트웨어 고정

| 패키지 | 버전 | 이유 |
|---|---|---|
| Python | 3.10 | 노트북과 동일 |
| torch | 드라이버 CUDA 에 맞춤 (cu130 또는 cu124) | 드라이버가 상한 |
| **ultralytics** | **8.4.102** | 증강 기본값·손실·평가 방식이 버전마다 달라 비교가 깨진다 |
| opencv-python | 5.0.0.93 | |
| albumentations | **설치 여부를 기록** | 설치돼 있으면 ultralytics 가 Blur·MedianBlur·ToGray·CLAHE 를 각 1% 확률로 **자동 적용**한다. 노트북에는 없다 → 켜고 끄는 게 실험 변수가 된다 |

> [!warning] 8.4.102 에서 확인한 것 (노트북 설치본 기준)

> - `multi_scale` 은 참/거짓이 아니라 **실수(비율)** 다. 기본 0.0
> - `yolo26` 계열과 `yolo26-p2.yaml`, `yolov8-p2.yaml` 이 들어 있다. `yolo11-p2` 는 없다

## 3. 작업 규칙

| 규칙 | 방법 |
|---|---|
| 학습은 tmux 에서 | `tmux new -s s2_jitter` → `Ctrl+B, D`. 세션 이름 = 실험 이름 |
| 실험 이름 규칙 | `s<단계>_<바꾼것>_<값>` 예: `s2_jit_wide`, `s4_y26s_1280` |
| 끝나면 바로 백업 | `best.pt` · `last.pt` · `results.csv` · `args.yaml` → 노트북으로 복사 (대여 서버) |
| 체크포인트 | `save_period=10` — 10 에폭마다 저장해 두면 best 이외 시점도 평가할 수 있다 |
| 진행 기록 | `SERVER_PROGRESS.md` 에 쓰고 **push** — 노트북 옵시디언에서 볼 수 있게 |
| 데이터 | NOMAD·WiSARD·Okutama 와 파생물은 **git 에 올리지 않는다** |
| 안전자산 | `weights/yolov8s_stage1_all.pt` 는 덮어쓰지 않는다 |

## 4. 기준선 재현

**같은 가중치를 서버에서 다시 재서 노트북 값과 맞는지** 먼저 본다.

| 무엇 | 명령 | 기대 | 허용 |
|---|---|---|---|
| stage1_all 도메인별 | `python eval_domain.py --imgsz 960 --weights weights/yolov8s_stage1_all.pt` | 여름 0.641 · 겨울 0.922 | ±0.01 |
| 크기 곡선 | `python eval_scale.py --weights weights/yolov8s_stage1_all.pt` | 320 입력 여름 재현율 0.387 | ±0.02 |
| 속도 | `python bench_models.py` (1920×1080 프레임, 전후처리 포함) | 3090 기준값을 **새로 기록** | — |

> [!note] 검증셋이 다르면 기대값도 다르다
> 서버 NOMAD val 은 12명이라 노트북(4명)과 다르다 → [[NOMAD 검증 배우 불일치]].
> 재현 확인은 **노트북과 같은 파일 목록**으로 하고, 이후 비교는 [[7 평가 프로토콜]] 의 공통 평가셋으로 한다.
