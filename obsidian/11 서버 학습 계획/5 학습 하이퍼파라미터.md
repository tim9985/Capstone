## 1. 한 파일로 고정한다

`train_person.py` 는 증강값·`cache False`·`workers 4` 가 코드에 박혀 있다(노트북 4 GB 기준).
실기체용은 **설정 파일 하나**로 관리해 실험마다 무엇이 달랐는지 남긴다.

```yaml
# configs/hyp_v2.yaml — 실기체용 1클래스 사람 탐지 (ultralytics 8.4.102)
# 모델·입력
imgsz: 1280
rect: false
single_cls: true
# 길이
epochs: 40            # 비교 실험. 최종 학습은 100
patience: 15          # 최종 25
close_mosaic: 10
save_period: 10
# 배치·시스템
batch: 16
nbs: 64
workers: 8
cache: disk
amp: true
seed: 42
deterministic: true
plots: true
# 최적화
optimizer: SGD
lr0: 0.01
lrf: 0.01
momentum: 0.937
weight_decay: 0.0005
warmup_epochs: 3.0
warmup_momentum: 0.8
warmup_bias_lr: 0.1
cos_lr: false
# 손실 가중치
box: 7.5
cls: 0.5
dfl: 1.5
# 색
hsv_h: 0.015
hsv_s: 0.7
hsv_v: 0.5

# 기하

# 합성
```

## 2. 인자별 이유

### 모델 · 입력

| 인자 | 값 | 기본값 | 프로토타입 | 이유 |
|---|---|---|---|---|
| model | **yolo11s.pt** (COCO) | — | VisDrone yolov8s → stage1_all | 서버 E 트랙과 같은 출발점. 후보 비교는 S4 |
| imgsz | **1280** | 640 | 960 | 크롭이 1280×720 → 축소 없이 들어간다. 960 이면 30 m 서 있는 사람이 16 px 로 무너진다 |
| rect | false | false | false | mosaic 과 함께 못 쓴다 |
| single_cls | true | false | — | 모든 라벨을 `person` 하나로 (SARD 자세 클래스 합치기) |

> [!note] 1280 보다 크게 학습하지 않는 이유
> 크롭 원본이 1280×720 이라 더 키우면 없는 정보를 늘리기만 한다. **추론만** 1600·1920 으로 키워 보는 건 S5 에서 한다.

### 길이

| 인자 | 값 | 기본값 | 이유 |
|---|---|---|---|
| epochs | 비교 **40** · 최종 **100** | 100 | 비교는 순위만 보면 된다. 서버 E1/E2 에서 15 에폭 근처부터 val loss 가 나빠졌다 — 데이터·증강이 늘면 더 버틴다 |
| patience | 15 · 최종 25 | 100 | 조기 종료와 `best.pt` 는 **fitness = AP50-95** 기준이다 (ultralytics 8.4.102 · 09-15 정정) → [[fitness와 조기 종료]] |
| close_mosaic | 10 | 10 | 마지막 10 에폭은 mosaic 없이 실제 장면 구성으로 마무리 |
| save_period | 10 | -1 | best.pt 는 AP50-95 위주로 뽑힌다. **10 에폭마다 저장**해 우리 판정 기준으로 다시 고른다 |

> [!warning] 초반 2~4 에폭 하락은 warmup 때문이다. 그걸로 끊지 않는다.

### 배치 · 시스템

| 인자 | 값 | 기본값 | 이유 |
|---|---|---|---|
| batch | **16 고정** | 16 | 첫 실행만 `-1`(자동)로 VRAM 60% 값을 확인하고 그 이하로 **고정**. 자동값은 실험마다 달라질 수 있다 |
| nbs | 64 | 64 | 배치 16 이면 4번 모아서 한 번 갱신 → 배치를 바꿔도 학습률 효과가 거의 같다 |
| workers | 8 | 8 | i9-11900 8코어 |
| cache | **disk** | false | 약 2만 장 × 1280 해상도 디코딩본 ≈ 50 GB → RAM 64 GB 에 올리면 위험. 디스크(.npy)는 5 TB 라 여유 |
| amp | true | true | 속도·메모리 |
| seed · deterministic | 42 · true | 0 · true | 재현. 차이가 0.01 미만인 비교는 seed 를 바꿔 한 번 더 |

### 최적화

| 인자 | 값 | 기본값 | 프로토타입 | 이유 |
|---|---|---|---|---|
| optimizer | **SGD 명시** | auto | auto | `auto` 는 반복 수 1만 미만이면 **AdamW** 로 바뀐다 (작은 데이터 파인튜닝에서 몰래 바뀜) |
| lr0 | **0.01** | 0.01 | 0.01 (stage1) / 0.001 (자세) | COCO 에서 **새로 배우는** 학습이다. 0.001 은 잘 된 모델을 **보존**할 때의 값 → [[8 실기체 적용]] 파인튜닝에서 쓴다 |
| lrf | 0.01 | 0.01 | | 마지막 학습률 = 0.01 × 0.01 = 0.0001 |
| momentum · weight_decay | 0.937 · 0.0005 | 같음 | | |
| warmup_epochs | 3 | 3 | | 처음 3 에폭 동안 학습률을 서서히 올린다 |
| cos_lr | false | false | | 선형 감소. 비교 변수를 늘리지 않는다 |

### 손실 가중치

| 인자 | 값 | 이유 |
|---|---|---|
| box · cls · dfl | 7.5 · 0.5 · 1.5 (기본) | 1클래스라 `cls` 는 사실상 "사람인가"만 본다. 바꿀 근거가 생기기 전까지 기본값 |

### 색 증강

| 인자 | 값 | 기본값 | 프로토타입 | 이유 |
|---|---|---|---|---|
| hsv_h | 0.015 | 0.015 | 0.02 | 색조를 크게 돌리면 옷·풀 색이 비현실적 |
| hsv_s | 0.7 | 0.7 | 0.8 | 데이터가 여름 한 곳(NOMAD)에서 여러 곳으로 늘어 기본값으로 충분 |
| hsv_v | **0.5** | 0.4 | 0.5 | 11~12월 **낮은 해 · 긴 그림자 · 역광** |

### 기하 증강

| 인자 | 값 | 기본값 | 프로토타입 | 이유 |
|---|---|---|---|---|
| **degrees** | **180** | 0 | 10 | 하향 영상엔 "위쪽"이 없다. 드론이 방향을 틀면 장면 전체가 돈다. 사람은 어느 방향으로든 눕는다 |
| **flipud** | **0.5** | 0 | 0 | 같은 이유 |
| fliplr | 0.5 | 0.5 | 0.5 | |
| translate | 0.1 | 0.1 | 0.15 | |
| **scale** | **0.3** | 0.5 | 0.5 | 전처리 크기 분포와 **곱해진다** → [[4 전처리 - 크기 정규화와 지터]] 4절 |
| shear | 0 | 0 | 0 | 기울임은 사람 모양을 비현실적으로 만든다 |
| perspective | 0 | 0 | 0 | 기체 기울기 흉내는 S6 에서 0.0003 으로 비교 |

> [!warning] degrees 180 의 부작용 — 박스가 부푼다
> 라벨이 박스뿐이라 회전하면 **네 모서리를 감싸는 더 큰 박스**가 된다.
> | 원래 박스 | 45° 회전 후 | 넓이 |
> |---|---|---:|
> | 누운 사람 107×31 | 98×98 | ×2.9 |
> | 이미 대각선인 누운 사람 98×98 | 139×139 | ×2.0 |
> | 서 있는 사람(하향) 21×21 | 30×30 | ×2.0 |
> 모델이 **헐거운 박스**를 배워 AP50-95 가 떨어질 수 있다.
> 대안: **90° 단위 회전(전처리) + 상하·좌우 반전 + degrees 15** → 8방향은 박스가 정확하고 사이각만 조금 부푼다. **S3 에서 비교**한다.

### 합성 증강

| 인자 | 값 | 기본값 | 이유 |
|---|---|---|---|
| mosaic | 1.0 | 1.0 | 4장을 이어 붙여 한 장에 사람·배경을 다양하게. 작은 물체에 특히 좋다 |
| mixup | **0** | 0 | 두 장을 반투명하게 겹친다 → 작은 사람이 **유령**처럼 흐려져 해롭다 |
| cutmix | 0 | 0 | 같은 이유 |
| copy_paste | 0 | 0 | 마스크 라벨이 필요하다. 인스턴스 은행은 보류 중 → [[결정 - Copy-Paste 보류]] |
| multi_scale | 0 | 0 | 1280 에서 쓰면 최대 1920 까지 커져 메모리·시간이 급증. `scale` 로 대신 |

### 검증

| 인자 | 값 | 이유 |
|---|---|---|
| val · iou · max_det | true · 0.7 · 300 | 기본. **학습 중 검증셋은 best.pt 선택용**일 뿐, 판정은 [[7 평가 프로토콜]] |

## 3. 데이터 설정 `configs/data_v2.yaml`

```yaml
# 경로는 반드시 절대경로 (상대경로면 configs/ 기준으로 풀려 죽는다)
train: /home/<user>/JupyterLAB/Capstone/drone_yolo/configs/train_v2_list.txt   # 각도별 반복 투입 목록
val:
  - /home/<user>/JupyterLAB/Capstone/drone_yolo/data/det_v2/val_balanced       # 출처별 균형 약 3,000장
nc: 1
names: ['person']
```

- 검증셋은 출처별로 **균형 있게 약 3,000장** — 서버 현재 val 4,968장은 매 에폭 검증이 길다
- 앞에서부터 자르지 말고 **고르게** 뽑는다 (WiSARD val 앞 291장은 사람이 없다 → [[함정 모음]])
