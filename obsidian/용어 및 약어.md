## 1. 속도 · 시간
| 용어 | 뜻 |
|---|---|
| **ms** | 1/1000초. 30 ms = 0.03초 → [[시간 지표 - ms·FPS·P95]] |
| **FPS** | Frames Per Second. 1초에 처리하거나 받는 영상 장수 |
| **P95** | 100번 재서 빠른 순으로 줄 세웠을 때 95번째 값. "대부분(95%)은 이 안에 든다" — 평균보다 엄격 |
| **추론** | 학습된 모델에 영상을 넣어 결과(사람 박스)를 얻는 것 |
| **전처리 · 후처리** | 추론 전 영상 크기 조정·변환 / 추론 후 겹친 박스 정리·결과 정리 |
| **버퍼** | 처리 대기 줄. 들어오는 속도가 처리보다 빠르면 쌓인다 |
| **지연** | 촬영부터 화면 표시까지 걸리는 시간 |

## 2. 탐지 평가지표
| 용어 | 뜻 |
|---|---|
| **IoU** | Intersection over Union. 두 박스가 겹친 정도 0~1 → [[IoU]] |
| **정밀도** | Precision. 잡은 것 중 진짜 사람 비율 → [[정밀도와 재현율]] |
| **재현율** | Recall. 진짜 사람 중 잡아낸 비율 |
| **TP · FP · FN** | 맞게 찾음 · 헛탐지 · 놓침 |
| **오탐** | 사람이 아닌 것(바위·그림자 등)을 사람으로 잘못 잡은 것 (FP) |
| **미탐** | 있는 사람을 놓친 것 (FN) |
| **AP** | Average Precision. 한 클래스의 정밀도-재현율 곡선 넓이 → [[AP와 mAP]] |
| **mAP** | mean AP. 여러 클래스 AP 의 평균. **우리는 사람 1클래스라 mAP = 사람 AP** |
| **AP50** | IoU 0.5 이상이면 정답으로 치고 계산한 AP. **우리 합격 기준** |
| **AP50-95** | IoU 0.50~0.95 10단계 AP 의 평균. 박스를 딱 맞게 쳤는지까지 봄. 참고용 |
| **신뢰도 점수** | 모델이 박스마다 붙이는 "사람일 가능성" 0~1 |
| **임계값** | 신뢰도 점수가 이 값 이상일 때만 "사람"으로 인정하는 기준선. 우리는 0.15 → [[신뢰도 임계값과 F2]] |
| **F2 점수** | 정밀도·재현율을 합친 점수. 놓치는 것을 헛탐지보다 무겁게 친다. 구조 목적이라 사용 |
| **NMS** | Non-Maximum Suppression. 같은 사람에게 쳐진 여러 박스 중 점수 높은 것만 남기는 후처리 |
| **클래스** | 모델이 구분하는 대상 종류. 우리 탐지 모델은 "사람" 하나 |
| **평가셋** | 성능을 재는 데 쓰는 영상 묶음. 학습에 쓰지 않은 것이어야 함 → [[도메인별 평가]] |
| **장소 분리** | 학습에 쓴 **장소**를 평가에 한 장도 넣지 않는 분할. 같은 장소면 0.86, 다른 장소면 0.22 → [[장소 일반화 - NFR-V03 0.22]] |
| **test_v2 · test_obl · test_kr** | 장소 분리 판정셋 — WiSARD 2곳(미국·수직) · Okutama 비스듬(일본) · AI-Hub 2곳(한국·90°) |
| **타일 추론** | 1920×1080 을 1280×720 4장(겹침 50 %)으로 잘라 추론 후 NMS 병합 → [[타일 추론]] |
| **TensorRT · FP16** | NVIDIA 추론 엔진 · 16비트 부동소수. 3090 에서 18.5 ms |
| **P2 헤드** | stride 4 검출층을 더한 YOLO — 작은 사람용 |
| **NWD** | Normalized Wasserstein Distance. 작은 박스에서 IoU 대신 쓰는 유사도 (Wang 2021) |
| **Wise-IoU** | 품질 낮은 박스의 기울기를 줄이는 박스 손실 (Tong 2023) |
| **연기 실행 (smoke)** | 긴 학습을 걸기 전 1에폭 + 평가 20장으로 끝까지 돌려 보는 것 |

## 3. 좌표 · 카메라 · 지도
| 용어 | 뜻 |
|---|---|
| **WGS84** | GPS 가 쓰는 위도·경도 좌표 체계 |
| **AGL** | Above Ground Level. 지면 기준 고도 |
| **GSD** | Ground Sample Distance. 영상 1픽셀이 땅에서 몇 cm 인가 → [[GSD와 화각]] |
| **HFOV · 화각** | 카메라가 담는 가로 각도. 렌즈 표기는 **대각** — 주 렌즈 대각 88° = **수평 80.2°** → [[GSD와 화각]] |
| **짐벌** | 카메라를 흔들림 없이 붙잡고 각도를 바꾸는 장치. **GM3 V2 3축** — 비행 중 피치 지정 |
| **마운트각** | 카메라 광축이 수평에서 아래로 기운 각. 90° = 수직 하향. 짐벌로 비행 중 지정 · **기본 60° (잠정)** (NFR-H02 "하향 30~90° 지원") → [[마운트각과 화면 기하]] |
| **기울기 (기체 자세)** | 비행 중 기체 몸체가 수평에서 기운 각도 (roll·pitch). 매 순간 바뀐다 (NFR-V04 "기울기 ≤ 6°"). 짐벌이 대부분 상쇄한다 |
| **roll · pitch · yaw** | 드론의 좌우 기울기 · 앞뒤 기울기 · 방향 |
| **안정 프레임** | GPS·고도·자세·시각이 유효하고 기울기 ≤6°, 자세 변화 ≤1.5° 인 영상 → [[NFR-V04 좌표 정확도]] |
| **좌표 보류** | 사람 후보는 유지하되 조건 미충족으로 좌표를 확정하지 않은 상태 |
| **대각 · 수평 화각** | 렌즈 표기(대각)를 16:9 가로로 환산. 88° → 80.2° · 78° → 70.4° · 62° → 55.3° |
| **비스듬 · 수직 시점** | 마운트각 < 90° 이면 비스듬 — 화면 위가 멀고 아래가 가깝다 |
| **DEM** | 수치표고모델. 지형 높이를 격자로 담은 지도 |
| **정사영상** | 기울기 왜곡을 보정해 지도와 겹쳐지는 항공사진 |
| **VWorld** | 국토교통부 공간정보 오픈플랫폼. 기본지도·건물 정보 |
| **상황지도** | 이번 임무의 관측·탐지 결과를 쌓은 지도 → [[상황지도와 기본 지도]] |
| **2.5차원** | 평면 지도 + 높이 값. 완전한 3D 는 아님 |
| **관측 완료도** | 구역 중 실제로 제대로 촬영한 면적 비율 → [[관측 완료도 계산 방법]] |
| **DSM** | 수치표면모델. 지형에 건물·나무 높이까지 더한 높이 격자 (DEM 은 지형만) |
| **가시권 분석** | Viewshed. 한 지점에서 무엇이 보이고 무엇이 가리는지 광선으로 계산 → [[관측 상태 판정 알고리즘]] |
| **점유 격자** | Occupancy Grid. 공간을 칸으로 나눠 칸마다 상태(비어 있음·막힘·모름)를 누적하는 지도 |
| **POD** | Probability of Detection. 수색 이론에서 "그 칸에 사람이 있었다면 찾았을 확률" |
| **KML** | 경로·좌표를 지도 프로그램에서 여는 결과 파일 형식 |

## 4-1. 학습 서버 · GPU 장애
| 용어 | 뜻 |
|---|---|
| **Xid** | NVIDIA 드라이버가 커널 로그에 남기는 GPU 오류 번호. 79 = GPU 가 PCIe 통로에서 사라짐 · 154 = 재부팅해야 복구 → [[GPU 장애 코드 Xid]] |
| **PCIe · Gen3/Gen4** | GPU 와 CPU 를 잇는 고속 통로와 그 세대. Gen4 가 두 배 빠르지만 신호가 예민하다 → [[PCIe 세대와 ASPM·AER]] |
| **ASPM · AER** | PCIe 절전 기능 · PCIe 오류 보고 기능 |
| **GSP** | GPU 안에 들어 있는 관리용 프로세서(펌웨어) |
| **sysrq** | 리눅스 커널에 바로 내리는 비상 명령. `b` = 즉시 재시작 → [[sysrq 강제 재시작]] |
| **전력 제한 · 클럭 상한** | GPU 평균 전력의 상한 · GPU 코어 작업 속도의 상한 → [[전력 제한과 클럭 상한]] |
| **systemd 서비스** | 리눅스가 부팅 때 자동으로 띄워 계속 돌리는 프로그램. 자동 복구 `gpu-autoheal` 이 이것 |
| **체크포인트** | 학습 중간 저장본. `last.pt` = 마지막 에폭 · `best.pt` = 최고 에폭 → [[이어 학습과 AutoBatch]] |
| **resume** | 체크포인트에서 에폭·학습률 스케줄을 그대로 이어 학습하는 것 |
| **AutoBatch** | GPU 메모리에 맞춰 배치 크기를 자동으로 고르는 Ultralytics 기능. 크게 틀릴 수 있다 |
| **MuSGD** | `optimizer auto` 가 반복 1만 번 이상일 때 고르는 최적화 방식 (ultralytics 8.4.102) |
