> [!warning] 10-07 발견 — 이 실험의 "추적" 은 실제로 추적이 아니었다
> - `state_pipeline.py` 의 `model.track(img, persist=k > 0)` → ultralytics 8.4.102 는 **첫 호출의 persist=False 를 콜백에 고정**해 **매 프레임 추적기를 새로 만든다** → 추적 ID = 그 프레임의 확신도 순번 (1 = 가장 확실한 사람)
> - 그래서 이력 (5초 중앙값 · 속도 · 무동작) 은 여러 사람이 섞인 값 · "ID 바뀜" 이 잦고 "자세 한 장" 이 가장 좋았던 이유
> - 한 장 자세 점수의 AUROC 자체는 유효 (이력을 안 씀) · 무동작 · 추적 단위 지표는 다시 재야 한다
> - 진짜 추적 (추적기를 직접 이어 씀) → worker `app/vision_core/state.py` · 판정 → [[V4 상태 인지 worker 이식 - 진짜 추적]]


> [!summary] 파이프라인이 누운 사람을 뒤로 밀던 원인은 **추적기 설정**이었다 — 고치니 요구조 점수가 누운 사람을 거의 다 앞으로 올린다
> - 원인: BoT-SORT 기본 `new_track_thresh` **0.25** > 탐지 운용 임계 **0.15** → 확신도 낮은 누운 사람이 새 추적을 못 만들고 **주변 사람 추적에 붙어** 앞사람 이력(자세 · 무동작)을 물려받음 → [[자세 판별 P0~P5 - C2A·상대 키·미세조정·파이프라인]] 진단
> - 고친 것: ① 추적 문턱을 운용 임계 0.15 에 맞춤 ② 1초에 몸높이 3배 넘게 튀면 ID 바뀜으로 보고 이력을 비움 ③ 자세 항은 지금 한 장 확률
> - **판정 (영상 반반 · A 에서 고르고 B 에서 판정)**: 점수 누움 AUROC **+0.172 (+0.048~+0.256)** · 잡힌 비율 +0.061 (0.000~+0.143) · 추적 단위 +0.046 (구분 안 됨) → 채택

- **추적 문턱 0.15** 는 누운 사람을 더 잡는다 (잡힌 비율 0.511 → 0.573) — 그런데 이력을 안 비우면 점수는 그대로 (V1 · agg 0.769) · 추적 단위는 오히려 나빠짐 (0.683 · 새 추적이 많아져 ID 가 더 자주 넘어감)
- **ID 바뀜 끊기** 가 있어야 누적이 다시 도움이 된다 (V2 · agg 0.940 — 정답 박스 P0 와 같은 방향)
- 자세 항을 한 장으로만 바꿔도 대부분 회복 (V0 · single 0.947) — 순위에는 "지금 누워 보이는가" 가 가장 강한 신호
- ⚠ **ReID (V3) 는 V2 와 모든 수치가 똑같다** — `model: auto` 가 실제로 켜졌는지 확인 필요 · 효과 판단 보류
- 추적 단위 AUROC 는 구간이 넓다 (B 의 누운 추적 수가 적음)
