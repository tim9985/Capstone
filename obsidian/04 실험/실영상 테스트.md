## 실시간 탐지 테스트기 (09-19)

`drone_yolo/detect_live.py` — **영상 경로만 주면 창이 뜨고, 재생 중에 설정을 바꿔 가며** 본다. 정답이 없는 영상용이라 수치 판정은 `eval_domain.py` · `eval_perflight.py` 로 한다.

```bash
python detect_live.py --source "data/raw/okutama/Drone2/Noon/2.2.10.mp4"
python detect_live.py --source <영상> --weights weights/m1_11m_1280.pt weights/yolov8s_stage1_all.pt
```

| 바꿀 수 있는 것 | 방법 |
|---|---|
| 신뢰도 · IoU | 슬라이더 · `+` `-` (±0.05) |
| 입력 크기 640 / 960 / 1280 / 1600 / 1920 | 슬라이더 · `[` `]` |
| 최대 탐지 수 · 최소 박스 크기(px) · 프레임 건너뛰기 · 재생 속도 | 슬라이더 |
| 가중치 교체 (여러 개 올려 두고) | `m` |
| 추적기 ByteTrack 켜고 끄기 | `t` |
| crop 모드 (4K 를 줄이지 않고 1280×720 만 잘라 넣기) | `c` · 창 이동 `i` `j` `k` `n` · 실행 옵션 `--crop 1280x720` |

- 화면 위에 **ms/frame · fps · 박스 수 · 평균 신뢰도 · 박스 긴 변 중앙값(px)** 을 띄운다 → 사람이 몇 px 로 잡히는지 바로 보인다
- `space` 재생·정지 · `a` `d` 한 프레임 · `b` 박스 px 표시 · `l` 라벨 · `s` 화면 저장 · `r` 주석 영상 녹화 · `q` 종료
- `--weights` 를 비우면 `drone_yolo/weights` 와 노트북 `drone_dev/weights` 에서 자동으로 찾는다 (자세 트랙 가중치는 제외) → [[결정 - 자세 판별 제외]]
- **4K 스톡 영상은 `c` 를 눌러 crop 으로 본다.** 4K 전체를 입력 1280 으로 줄이면 사람이 5~10 px 로 뭉개져 우리 운용 조건(18~133 px)과 전혀 다른 그림이 된다. 원본 해상도에서 1280×720 만 잘라 넣으면 사람 픽셀 크기가 실기체와 비슷해진다 → [[1 기준 조건 - 카메라·화각·마운트]]
- 윈도우에서는 `detect_live.bat` 에 영상 파일을 끌어다 놓아도 된다
- 서버 학습 가중치(`m1_11m_1280.pt` · `m2_11m_1280_sard.pt` 등)는 git 밖이라 **서버에서 직접 받아** `drone_yolo/weights/` 에 둔다 → [[학과 서버]]

## 서버 가중치 비교 (09-19 · 스톡 영상 15편)

정답 라벨이 없는 영상이라 **AP 가 아니다.** 속도와 "무엇을 잡고 무엇을 놓치는지"만 본 값이다.

**속도** — 3840×2160 프레임 1장 · RTX 3050 4 GB · 전후처리 포함 · 5회 중앙값

| 가중치 | 640 | 960 | **1280** | 1600 | 1920 |
|---|---:|---:|---:|---:|---:|
| fov 11s | 11.5 | 17.9 | **29.4** | 42.9 | 58.3 |
| fov 11m | 17.4 | 34.9 | **59.0** | 90.9 | 120.9 |
| L1 11l | 21.2 | 43.5 | **74.3** | 115.3 | 155.1 |
| v8s 운용(stage1_all) | 9.4 | 17.5 | **30.3** | 45.0 | 58.4 |

- 단위 ms. **노트북에서 NFR-V01(≤30 ms) 을 입력 1280 으로 지키는 건 11s 뿐이다** (11m 은 약 2배, 11l 은 2.5배). 실기체 보드 기준은 별도로 재야 한다
- 11s 를 1600 으로 키우면 42.9 ms → 1280 이 현재 타협점

**탐지** — 영상 15편 × 6프레임 · conf 0.15 · 입력 1280 (총 박스 / 평균 신뢰도 / 박스 긴 변 중앙값)

| 가중치 | 총 박스 | 평균 conf | 긴 변 중앙값 |
|---|---:|---:|---:|
| fov 11s | 341 | 0.39 | 111 px |
| fov 11m | 540 | 0.36 | 98 px |
| L1 11l | 435 | 0.38 | 105 px |
| v8s 운용 | 316 | 0.42 | 133 px |

- 11m 이 박스를 가장 많이 내지만 평균 신뢰도가 가장 낮다 — 미탐이 적은 건지 오탐이 많은 건지 **이 영상들로는 구분할 수 없다**. 판정은 라벨 있는 홀드아웃(공통 10명)에서 한다 → [[7 평가 프로토콜]]
- 사람이 크게 찍힌 영상(누운 사람 포함)은 네 모델 모두 찾는다. 갈린 건 작은 사람뿐이다

**full 과 crop 비교** — 같은 프레임 5장씩 (박스/장, full → crop)

| 영상 | 11s | 11m | 11l | v8s |
|---|---|---|---|---|
| 시장(사람 100+명) | 0.4 → 1.0 | 0.8 → 0.8 | 1.0 → 0.8 | 5.2 → 5.6 |
| 해변 인파 | 20.6 → 4.4 | 53.0 → 5.0 | 38.4 → 6.8 | 17.2 → 2.4 |
| 들판 | 1.6 → 1.4 | 2.2 → 2.2 | 2.2 → 1.8 | 3.6 → 0.6 |
| 주차장 | 5.6 → 2.4 | 2.2 → 2.0 | 3.0 → 4.6 | 2.6 → 1.4 |
| 누운 사람 | 1.0 → 0.6 | 1.2 → 0.6 | 1.2 → 1.4 | 0.6 → 0.2 |

- crop 은 화면에 든 사람 수 자체가 줄어 박스 수도 준다. 대신 **신뢰도가 올라간다** (들판 11s 0.42 → 0.61)
- **가장 중요한 결과**: 시장 영상은 눈으로 100명 넘게 보이는데 full 은 네 모델 모두 0~6개만 냈다. crop 으로 봐도 11s 2개 · 11m 0개 · 11l 2개 · v8s 9개다. 스톡 4K 는 촬영 고도가 우리 운용(16~30 m)보다 훨씬 높아 **사람이 20 px 아래로 찍힌 장면이 많다** — 모델 문제라기보다 조건 밖이다
- 즉 **스톡 영상은 "우리 조건과 얼마나 다른지" 확인용이고, 성능 판정용이 아니다.** 판정에 쓸 영상은 16~30 m 하향으로 직접 찍어야 한다 → [[05 실기체 적용 - 자체 촬영]]
