## 2. 원인 ① 과녁이 틀렸다 — 우리 AP 는 "작은 박스" 에서 새지 않는다

- NWD 설계 대상: AI-TOD (평균 **12.8 px**) · 우리: test_obl 긴 변 중앙 **38 px** · 학습 크롭 45 px · 24 px 미만은 test_obl 7.5 %
- **test_obl 에서 AP 가 새는 곳 = 박스 모양 차이**
  - IoU 기준만 낮추면: AP30 **0.845** ↔ AP50 0.626 → **22 %p 가 "찾았지만 박스가 다름"**
  - 위치 어긋남(IoU 0.3~0.5) 778명 · 긴 변 중앙 **37 px** (작은 사람 아님) · 우리 박스 **너비비 0.69** (좁다) · 중심 어긋남 너비의 18 %
  - 중심만 맞춰도 58 % 가 IoU 0.5 통과 → **Okutama 라벨 습관** (넓고 약간 밀린 박스 · 영상 보간) — 학습 손실로 못 고치고, 고쳐서도 안 된다 (Okutama 는 평가 전용)
  - test_v2 는 AP30 0.648 ↔ AP50 0.527 (12 %p) · 너비비가 양쪽으로 퍼짐 (0.59~1.42) = 진짜 위치 오류
- 운용 범위(≥24 px) 에서 **진짜로 놓치는 층** — NWD·P2 둘 다 못 올림

## 3. 원인 ② NWD 의 부작용 — 확신도가 부풀었다

| test_obl | v6_obl | r2 | **NWD** | P2 |
|---|---:|---:|---:|---:|
| 찾은 사람 확신도 중앙 | 0.724 | 0.719 | **0.798** | 0.696 |
| 오탐 (conf ≥0.5) | 882 | 876 | **1,060** (+21 %) | 694 |
| 정밀도 @재현율 0.2 | 0.892 | 0.897 | **0.851** | 0.893 |
| 찾은 수 (conf ≥0.15) | 4,421 | 4,384 | 4,378 | 4,278 |

- test_v2 도 같다: 확신도 0.625 · 0.606 → **0.708** · 오탐(≥0.5) 467 · 506 → **614**
- 같은 설정 반복끼리는 0.005 차이 → **NWD 고유 현상**
- 기전: 양성 할당(TAL)은 **겹침 값으로 분류 목표 점수**를 만든다. NWD 는 같은 어긋남에 더 큰 값을 준다
  - 예: 19×38 px 사람 · 3 px 어긋남 → IoU **0.73** ↔ NWD **0.91** (C 32 px)
  - → 모든 양성의 목표 점수 ↑ → 애매한 배경까지 높은 점수 → **상위 순위 정밀도 ↓** → AP ↓
- 재현율·찾은 IoU·박스 비는 그대로 (68.0 vs 68.1 % · IoU 중앙 0.678 vs 0.674) — 얻은 것 없음
- val mAP50-95 도 낮다 (최종 0.433 vs 0.440) — 높은 IoU 구간에서 CIoU 보다 느슨

## 4. 원인 ③ P2 — 더 조심스러운 모델

- 오탐 (≥0.15) 2,235 → **1,725 (−23 %)** · 대신 찾음 68.7 → 66.4 % · 누운 0.323 → 0.247 · 앉은 0.503 → 0.438
- 16 px 미만 재현율 그대로 (0.038 → 0.031) — 작은 사람은 해상도가 아니라 **정보 부족**
- 추정: 작은 격자(stride 4)가 24~50 px 사람 할당을 가져가 넓은 맥락을 덜 본다 → 흔치 않은 자세에 약함
- → AP 이득 없음 · 추론 비용만 ↑ → **안 쓴다** (유지)

## 5. 원인 ④ 판정 잡음 — 같은 설정 두 번이 3.4 %p

- r2 는 v6_obl 과 **설정이 같고 학습 순서만** 다르다 → test_kr 에서 +3.4 %p **"차이 있음"**
- 짝 부트스트랩은 **평가셋 표집** 흔들림만 잰다 · **학습 실행** 흔들림은 안 잰다
- 손실·머리 바꾸기의 기대 효과(1~2 %p) < 실행 흔들림 → 한 번 학습으로 판정 불가
- 크게 오른 건 **데이터뿐**: v3_place → v6_obl +42.6 %p (test_obl) · +30.5 %p (test_v2)

## 6. 공짜 이득 — 가중치 평균 (수프)

- 같은 COCO 가중치에서 출발한 두 모델의 가중치를 그대로 평균 (`soup.py` · Wortsman 2022 · DiWA 2022)
- 세 평가셋 모두 **재료 평균보다 높다** (+1.9 · +1.6 · +0.7 %p) · test_obl 은 두 재료 각각보다 유의하게 높다
- **추론 비용 0** (모델 하나) — 실행 흔들림을 평균으로 줄인다

> [!danger] 손실이 다른 모델은 섞지 않는다 — 3개 수프 (v6_obl + r2 + **NWD**)
> test_obl **+9.0 %p** (0.7083) 인데 test_v2 **−6.8** · test_kr **−19.7 %p** → ❌ 폐기
> 박스가 넓어졌다 (너비비 중앙 0.889 → **1.017**) → 넓게 그리는 Okutama 라벨과 **우연히** 맞아 위치 어긋남 12.8 → 6.8 %
> 교훈: **평가셋 하나의 큰 이득은 라벨 습관일 수 있다** — 세 평가셋 모두 + 박스 너비비를 같이 본다

> [!danger] 데이터가 다른 모델도 섞지 않는다 — soup_v67 (v6_obl + r2 + **v7**)
> test_obl +7.0 %p 인데 test_v2 −10.6 · test_kr **−44.3 %p** → ❌ · 수프는 **같은 데이터·같은 설정의 반복**끼리만
