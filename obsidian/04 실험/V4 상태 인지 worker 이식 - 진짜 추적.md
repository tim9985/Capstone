> [!summary] 상태 인지 (추적 → 자세 · 무동작 → 등급 · 점수) 를 worker 에 넣었다 — 그 과정에서 **연구 파이프라인이 추적을 못 하고 있었다**는 걸 찾았다
> - worker: `app/vision_core/state.py` → 모든 관측에 `state` (REAL) · SIM 은 칸이 없어 추적만 후보 묶기에 씀
> - **발견**: `model.track(img, persist=k > 0)` 는 ultralytics 8.4.102 에서 **매 프레임 추적기를 새로 만든다** → 10-01~10-07 상태 연구의 "추적 ID" 는 프레임마다 확신도 순번이었다
> - 판정 (미리 정한 기준 ≥0.90 · ≥0.50): 1차 ❌ (잡힌 비율 0.496) → 원인 분리 → 확정 전 탐지에도 한 장 자세 상태 → 2차 ✅

| 실행 | 탐지 · 추적 영상 · 채점 박스 | 점수 누움 AUROC (95 %) | 누움 잡힌 비율 | 판정 |
|---|---|---:|---:|---|
| 연구 Q1 V2·single (참고) | 전체 · 720p · 추적기 | 0.953 | 0.573 ⚠ 버그로 부풀림 | — |
| 1차 v9x2 | **타일 · 1080p · 탐지** | 0.917 (0.79~0.98) | 0.496 | ❌ |
| 1차 v7r2 (참고) | 타일 · 1080p · 탐지 | 0.905 (0.78~0.97) | 0.511 | ✅ |
| 분리 ① | 전체 · 1080p · 탐지 | 0.933 | 0.496 | 탐지 아님 |
| 분리 ② | 전체 · **720p** · 탐지 | 0.940 | 0.496 | 영상 크기 아님 |
| 분리 ③ | 전체 · 720p · **추적기 박스** | 0.939 | 0.481 | 채점 박스 아님 |
| 분리 ③' | 타일 · 1080p · 추적기 박스 | 0.916 | 0.489 | |
| **2차 v9x2** | 타일 · 1080p · 탐지 · **확정 전 한 장 상태** | **0.916 (0.78~0.98)** | **0.557** | ✅ |
| 2차 v7r2 (배포 모델) | 같음 | 0.905 (0.79~0.97) | 0.573 | ✅ |

- 차이의 정체: 같은 영상 2.1.2 의 210번 프레임 — 연구는 누운 사람 (확신도 0.44) 을 "추적 4번" 으로 표본에 넣었지만 진짜 추적기는 카메라가 움직여 놓친 뒤 **새 추적 (확정 전)** 으로 다시 시작 → 출력 안 함
- 같은 탐지를 `model.track` 과 직접 `BOTSORT.update` 에 넣어 비교 → `model.track` 은 210번에서 ID 1~8 (전부 순번) · 직접은 1 · 2 · 3 (확정된 것만)
- AUROC 는 타일 탐지에서 약 0.02 낮다 (0.933 → 0.917) — 구간 안 · 운용은 타일 그대로 (작은 사람 재현율 때문)
- 속도: 탐지 + 상태 중앙 56 ms · P95 111 ms (PyTorch FP16 · 3090) → 초당 ~17장 (NFR-V02 ≥5 ✅) · TensorRT 면 더 빠름

## 진짜 추적으로 처음 본 것

| 정답 자세 | 속도 잰 비율 | 이동 중 | 무동작 중앙 | 무동작 ≥10초 | 누움 확률 중앙 |
|---|---:|---:|---:|---:|---:|
| 누움 | 0.80 | 0.06 | 1초 | **0.05** | 0.59 |
| 앉음 | 0.85 | 0.08 | 2초 | 0.16 | 0.31 |
| 서기 | 0.86 | 0.12 | 2초 | 0.14 | 0.14 |
| 걷기 | 0.91 | 0.63 | 0초 | 0.02 | 0.17 |

- **URGENT 가 안 뜨는 이유** = Okutama 배우는 잠깐만 눕는다 (10초 넘게 누운 표본 5 %) + 누움 확률 중앙 0.59 (< 0.7) → 데이터 · 문턱 문제 · 버그 탓만은 아님
- 서 있는 사람도 14 % 가 10초 넘게 멈춰 있다 → 무동작만으로는 못 가른다 (자세와 같이 써야)
