> [!summary] "고도를 알면 사람을 목표 px 로 맞춰 넣자"를 검증했다
> 도구 `eval_fullframe.py --imgsz 1280 1600 1920 2560 3200` · 결과 `metrics/eval_fullframe_fov_11m_1280_all.csv`

## 왜 했나

학습과 추론의 크기 처리가 어긋나 있었다.

| 단계 | 처리 |
|---|---|
| 학습 | 원본을 리샘플해 사람 긴 변을 **로그 균등 16~160 px** 로 맞춘 뒤 1280×720 창을 오려낸다 |
| 추론 | 원본 1920 프레임을 **그대로** 넣는다 |

추론 시점에 고도·화각을 알 수 있으므로 프레임을 리샘플해 사람을 일정 px 로 맞출 수 있다.
네이티브를 넘겨 확대하면 사람 px 가 커지므로, **입력 크기 스윕이 곧 GSD 정규화 실험**이다.

| 추론 입력 | 서 있는 사람 | 누운 사람 |
|---:|---:|---:|
| 1280 | 25.3 px | 85.3 px |
| 1600 | 31.7 | 106.7 |
| **1920 (네이티브)** | **38.0** | **128.0** |
| 2560 | 50.7 | 170.7 ← 학습 상한 160 초과 |
| 3200 | 63.3 | 213.3 ← 초과 |

## 조건

- 모델 `fov_11m_1280_all` (yolo11m · 1클래스) · conf 0.15 · IoU 0.5 1:1 매칭
- 시험셋 `data/det_fullframe` — 1920×1080 전체 프레임 · s38(서 있는 38 px) 1,673장 · l128(누운 128 px) 869장 · neg(사람 없음) 187장
- **L2 학습과 GPU 를 나눠 쓰는 중이라 시간은 약 2.55배 부풀려져 있다** (단독 실행 시 1920 = 30.8 ms)

## 읽어낸 것

### 1. 재현율과 오탐이 같은 방향으로 움직인다 → 고정 임계값 비교는 교란돼 있다

s38 재현율@0.15 0.283 → 0.315 → 0.344 → **0.290** → **0.417** 은 단조가 아니다.
그런데 오탐도 1.115 → 1.381 → 1.533 → **1.103** → **2.012 건/프레임**으로 **같이 움직인다.**

입력 크기가 바뀌면 신뢰도 분포가 이동하는데, **conf 0.15 고정으로 재면 그 이동이 재현율 변화로 보인다.**
탐지 능력 변화와 보정(calibration) 변화를 분리하려면 **AP(임계값 무관) 또는 오탐을 맞춘 뒤의 재현율**이 필요하다.

오탐 1건당 재현율로 보면 순서가 또 달라진다:

| 입력 | 1280 | 1600 | 1920 | 2560 | 3200 |
|---|---:|---:|---:|---:|---:|
| s38 재현율@0.15 ÷ 오탐(건/프레임) | 0.254 | 0.228 | 0.224 | **0.263** | 0.207 |

> [!warning] 같은 함정을 반복했다
> [[서버 L1 - yolo11l 1280]] 에서 "40 m 칸 재현율@0.15 **상대 +9.5 %** · 같은 칸 **AP50 상대 −19.5 %**" 로 확인한 것과 같은 구조다.
> **재현율 단독 비교 금지** 규칙을 이 실험 설계에서 지키지 못했다.

### 2. 큰 대상(누운 사람)은 확대가 명확히 해롭다

| | l128 재현율@0.15 | 오탐(건/프레임) |
|---|---:|---:|
| 1600 (107 px) | **0.657** | 0.891 |
| 1920 (128 px) | 0.643 | 0.873 |
| 2560 (171 px) | 0.499 | 0.703 |
| 3200 (213 px) | 0.555 | **1.725** |

3200 에서는 **재현율@0.15 이 내려가고 오탐(건/프레임)이 2배로 오른다** — 교란 없이 나빠진 경우다.
학습 상한 160 px 를 넘어가는 구간이라 외삽이다.

### 3. 시간이 판정을 끝낸다

단독 환산으로도 2560 ≈ 48 ms · 3200 ≈ 74 ms 로 [[NFR-V01 추론 시간]](≤30 ms)을 넘는다.
**성능 해석과 무관하게 업스케일은 운용 불가**다.

### 4. 1600 이 실용 최적으로 보인다

| 지표 | 1600 | 1920 |
|---|---:|---:|
| 누운 128 px 재현율@0.15 | **0.657** | 0.643 |
| 서 있는 38 px 재현율@0.15 | 0.315 | **0.344** |
| 음성 프레임 오탐 (건/프레임) | **0.326** | 0.401 |
| 시간 | **24.0 ms** | 30.8 ms (경계) |

서 있는 38 px 에서 **−2.9 %p**(0.344 → 0.315 · 상대 −8.5 %)를 내주고 **누운 사람 · 오탐 · 시간을 모두 얻는다.**
1920 은 NFR-V01 경계(30.8 ms)라 4080 SUPER 실측 전에는 여유가 없다.

## 판정

| 항목 | 결론 |
|---|---|
| **업스케일 방향 GSD 정규화** | **기각** — 시간 3.5~5배 · 큰 대상은 명확히 손해 · 작은 대상은 교란돼 판단 불가 |
| 다운스케일 방향 | 미검증. 저고도에서 사람이 크게 찍힐 때 축소하면 시간을 아낄 수 있다 (1280 에서 누운 128 px 재현율@0.15 은 0.643 → 0.625 로 **−1.8 %p** · 상대 −2.8 % 뿐) |
| 임계값 재조정 | **필요** — 입력 크기마다 신뢰도 분포가 다르다. [[NFR-V05 신뢰도 기준]] 의 F2 탐색을 입력 크기별로 해야 한다 |
| 운용 입력 크기 | **1600 검토** (현재 기본 1920) |
