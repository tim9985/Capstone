## 1. % 와 %p 를 구분한다

| 표기 | 뜻 | 예 |
|---|---|---|
| **%p** (퍼센트포인트) | 두 값의 **뺄셈** | 재현율 0.3444 → 0.3729 은 **+2.9 %p** |
| **상대 %** | 두 값의 **나눗셈** | 같은 변화가 **상대 +8.3 %** |

- 0~1 지표(재현율·정밀도·AP·F2)는 **%p 를 먼저**, 상대 %를 괄호에 쓴다
  → `0.3444 → 0.3729 (**+2.9 %p** · 상대 +8.3 %)`
- 시간 · 장수 · 데이터 양처럼 0이 기준인 양은 **상대 %만** 쓴다 (예: 시간 −35 %)
- 상대 %를 단독으로 쓸 때는 **"상대"를 반드시 붙인다**

> [!warning] 왜 중요한가
> 재현율 0.20 → 0.22 와 0.80 → 0.88 은 **둘 다 상대 +10 %** 지만 %p 로는 +2 %p vs +8 %p 다.
> 우리는 재현율이 0.2~0.6 구간에 흩어져 있어 상대 %만 보면 작은 칸의 변화가 과대평가된다.

## 2. 0.xxx 앞에 **어떤 지표인지** 쓴다

| 쓰는 말 | 뜻 |
|---|---|
| **재현율@0.15** | conf 0.15 에서의 재현율. 우리 운용 임계값 → [[NFR-V05 신뢰도 기준]] |
| **정밀도@0.15** | 같은 임계값의 정밀도 |
| **AP50 (IoU 0.5)** | 임계값 전 구간 PR 곡선 면적. **임계값과 무관** |
| **AP50-95** | IoU 0.5~0.95 평균 |
| **val mAP50** | 학습 중 ultralytics 가 찍는 값. 사람 1클래스라 **AP50 과 같은 값**이지만, 로그 표기 그대로 쓸 때만 이 이름을 쓴다 |
| **F2** | 5PR/(4P+R) · 재현율 가중. 차이는 **F2 절댓값**으로 적는다 (%p 아님) |
| **오탐 (건/프레임)** | 프레임당 오탐 개수. `%` 를 붙이지 않는다 → [[NFR-V06 프레임 오탐]] |

- **fitness 는 mAP50-95 만**이다 (ultralytics 8.4.102) — best.pt 선정 근거를 적을 땐 이걸 명시 → [[fitness와 조기 종료]]
- 재현율은 **AP 와 짝으로** 적는다. 재현율만 올라가고 AP 가 떨어지는 경우를 두 번 겪었다 → `CLAUDE.md` §4-11

## 3. 조건을 함께 적는다

숫자 하나에 최소 이만큼은 붙어야 뒤에서 읽을 수 있다:

```
서 있는 38 px · 재현율@conf 0.15 · IoU 0.5 · 입력 1920 FP16 · 시험셋 det_fullframe/s38
```

- **대상 크기**는 px 로 (칸 이름 s38 = 38 px) → [[1-1 조건별 사람 px 범위표]]
- **입력 크기 · 정밀도(FP16/FP32) · 타일 여부**는 시간을 적을 때 항상
- **시험셋 이름**과 장수

## 4. 흔한 실수 (실제로 냈던 것)

| 실수 | 바로잡기 |
|---|---|
| "가장자리 −24.6 %" | 어느 지표인지 없다 → **재현율@0.15 −7.7 %p (상대 −24.6 %)** |
| "close_mosaic L1 −9.9 %" | 구간이 틀렸다 — 20→30에폭 값이었다. 해제 구간(25→30)은 **−3.6 %** |
| "오탐 +48 %" | 건/프레임인지 비율인지 모른다 → **0.401 → 0.594 건/프레임** |
| "AP50 0.4" | 어느 셋인지 없다 → **16~160 px 크롭 val** 인지 **장소 분리 시험셋**인지로 의미가 완전히 달라진다 → [[NFR-V03 탐지 정확도]] |
