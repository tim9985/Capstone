## 1. 시연 검증 (시스템 ↔ UE) — 비전 확인표

- [ ] SIM · REAL `readiness.model_loaded = true` · 상태 파일 `backend = tensorrt` · 모델 `v12_f91_swa` · 임계값 0.20
- [ ] **GPU 에 학습이 돌지 않음** (시연 · 측정 시간에는 학습 멈춤 — 같은 3090 공유) · 지금 의사 라벨 학습은 10-17 오전에 끝남

- [ ] 인상착의 조건 (예: green) 을 관제 API 로 넣어 둠 → 프레임 응답에 실려 오는지

### 화면에서 볼 것 · 정상인 것

| 항목 | 정상 | 원인 · 설명 |
|---|---|---|
| 좌표 | **전부 PENDING (`GROUND_UNKNOWN`)** | UE 고도 = 해수면 기준 · 지면 높이 없음 → 평지로 채우지 않는 규칙 (통합 v1.2) · 비전 계산 자체는 UE 정답 대비 중앙 ≈ 1 m |
| 후보 수 | 사람당 3~5 | 알려진 약점 (추적 ID 바뀜 · 좌표 보류 탐지) · 외형 (ReID) 개선 판단 대기 |
| 처리 지연 | 업로드 대기 늘 수 있음 | 0.2 s 설정이 5 fps 지속 수신 보장 아님 (요청 4개 · 각 ≈ 0.2 s) |
| 탐지 시간 | ≈ 22 ms / 장 | TensorRT · 인수 검증 AP50 0.6417 |

### 시연 전 팀에 확인할 것

1. **UE 카메라 수평 화각 = 80.2°** 인지 (worker 가정 · 다르면 좌표 · 크기 해석 틀림)
2. UE 지면 높이 (AGL 또는 지형 높이) 를 pose 에 넣을 수 있는지 — 넣으면 좌표 표시 가능
3. 시연 시간 GPU 비우기 규칙

### 실시간 시연 방식 — B (UE 담당 노트북 · 10-17 사용자 결정)

- 확인 (로컬 세션 10-17): UE 장면 (Vision_S1 · S4 · S5) · 카메라 (수평 80.2° · 1920×1080) ✅ · **연결기 코드 · 이 PC 용 SIM 신원 · 임무 UUID 없음** ❌ (지난 CAPTURE 시험은 통합 담당 PC)
- 순서 (`drone-dev/docs/SERVER-SIMULATION.md`): ① 통합 담당 → NET_SITL 연결기 소스 · 새 SIM worker 신원 ② 사용자 터널 (18443 · 18444) ③ 관제 simulation-lab 에서 SIM 임무 · PC · 맵 · `pipeline_config` (모델 id · 0.2 s · JPEG) ④ 로컬 검사 → CAPTURE 왕복 → 빈 장면 · 6명 · 8색 촬영
- 위험: 관제 맵 목록에 VisionEval 레벨이 없을 수 있음 · 연결기는 SimpleFlight (멀티콥터) 로만 시험됨 → 안 되면 정지 호버 settings 사본
- 예비안 C: 우리 UE 녹화 (pose 포함) 재생 시연
