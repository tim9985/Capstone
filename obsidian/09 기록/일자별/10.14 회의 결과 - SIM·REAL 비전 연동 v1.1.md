# 10-14 회의 결과 — SIM·REAL 비전 연동 v1.1 (통합 담당 문서)

> [!summary] 회의 전 요청 4개가 **모두 연결됨** (UE 녹화 · SIM 경로 · REAL 탐지 · 프레임 pose) — 다만 배포된 worker 는 **탐지 · 후보 (화면 IoU) · 색** 까지만이고 좌표는 전부 보류 · 추적 · 상태 · 인상착의는 아직 안 들어감
> 비전이 할 것: ① 배포 모델 **v12_f91_swa · 0.20** 으로 등록 교체 (통합 담당 · 해시 검증) ② `frame-pose/1.0` 을 좌표 입력으로 ③ 추적 · 상태 · 인상착의를 배포 worker 에 ④ 정확도 · 개수 · 크기 제한 검증 (비전 책임)

## 1. 회의 전 요청 → 지금

| 요청 (10.14 회의 자료 §4) | 지금 (통합 v1.1) | 남은 것 |
|---|---|---|
| 1. UE 비행 녹화 → 비전 전 과정 | ✅ 비전이 직접 10회 (16 · 20 m) → [[18 UE 비전 전 과정 검증 (10-14)]] | 추적 · 후보 · 누움 · 색 개선 |
| 2. SIM 연결 (UE 프레임 → 분석 · pose · GPU) | ✅ UE CAPTURE 1회 frame 4 · pose 4 · 분석 4 · 관측 12 · 미전송 0 · SIM worker CUDA (CPU 2 · RAM 4 GiB) | 실행 요청에 `pipeline_config` (임무 · 모델 id · 카메라 · 2 s 간격) |
| 3. REAL 탐지 (`vision_ingest`) + GPU + 모델 등록 | ✅ REAL 도 `app.vision_ingest` · CUDA · 모델 등록 (soup_v7r2) | **v12_f91_swa 로 다시 등록** · TensorRT 켜기 |
| 4. 프레임 pose | ✅ `frame-pose/1.0` (REAL `GET /internal/v1/frames` · SIM 분석 run 메타) | 좌표는 **전부 PENDING** (`POSE_MISSING` · `PHYSICAL_VALIDATION_REQUIRED`) · UE `mount` = null (짐벌 보정 없음) |

## 2. 구성 (요약)

| | SIM | REAL |
|---|---|---|
| 입력 | UE 이미지 + camera pose → SSH 터널 → SIM API (해시 검증) → 분석 job | 현장 gateway → REAL API |
| worker | `app.vision_ingest` · claim · attempt · completion | `app.vision_ingest` · JSONL · ACK · receipt (mTLS + Bearer) |
| DB | 기존 개발 DB | 별도 REAL DB |
| 모델 | soup_v7r2 · PyTorch FP16 (TensorRT 안 켬) | 같음 · 모델 id 는 환경마다 따로 (섞지 않음) |
| 네트워크 | `network_mode: none` · GPU 3090 공유 | 같음 |

- 모델 파일 · manifest · 등록 해시를 **불러오기 전에** 확인 → **파일만 바꿔 넣으면 안 됨** (새로 등록해야 함)
- `readiness.model_loaded` = 등록 해시와 맞는 worker 보고 (45 s 유효) — 정확도 · 좌표 검증을 뜻하지 않음

## 3. `frame-pose/1.0` (비전 입력)

| 필드 | 뜻 | 비전 쓰임 |
|---|---|---|
| `clock_domain` · `source_timestamp_ns` · `body_timestamp_ns` · `sync_error_ms` | 이미지 · 기체 snapshot 시각과 차이 (REAL 은 UTC / DEVICE_MONOTONIC 만) | 동기 오차 큰 장은 좌표 보류 (지금 `MAX_GAP_S` 0.5 s) |
| `geographic` | 위경도 · 고도 · 고도 기준 (MSL / ELLIPSOID / AGL / RELATIVE_HOME) | 지면 높이 기준 맞추기 (AGL 아니면 DEM 필요) |
| `camera_attitude` · `camera_position_ned` | 카메라 NED 방향 (quaternion) · 위치 | **발끝 광선을 이것으로 직접** — 짐벌 · 마운트 가정 없이 |
| `body_attitude` · `mount` | 기체 자세 · 짐벌 / 고정 · 보정 id | 카메라 자세가 없을 때만 |
| `missing_reasons` | 못 준 항목 | 그대로 보류 사유로 |

- 규칙: 빠진 자세를 0° · 짐벌 −45° · 평지로 **채워 좌표를 만들지 않는다** · worker 의 VALID 는 별도 근거로만 저장 (공식 위치로 승격 안 함)

## 4. 지금 배포된 worker 와 우리 worker (1.2) 차이

| 기능 | 배포 (통합 판) | 우리 1.2 (UE 검증한 판) |
|---|---|---|
| 탐지 · 경계 합치기 | ✅ | ✅ |
| 임계값 기본 | 0.15 | **0.20** |
| 후보 묶기 | 화면 IoU 만 (좌표 없음) | 좌표 문 + 추적 키 |
| 좌표 | 항상 PENDING | 발끝 광선 × 지면 · 보류 사유 |
| 추적 · 상태 (요구조자) | ❌ (`state: null`) | ✅ BoT-SORT · 누움 점수 · 등급 |
| 인상착의 질의 · 재관측 제안 | ❌ | ✅ |

→ 중간발표 시연에서 관제 화면에 **좌표 · 상태 · 질의 결과는 지금 안 뜸** — 아래 할 일 2 · 3

## 5. 비전 할 일

1. **모델 교체 요청** (통합 담당) — `v12_f91_swa` · SHA-256 `d2a4edc9…3772` · conf 0.20 · SIM · REAL 각각 새 모델 id · TensorRT 엔진 (worker 검증 AP50 0.6417 = .pt 0.6426 · 21 ms) → [[결정 - 배포 탐지 모델 v12_f91_swa · 임계값 0.20]]
2. **pose → 좌표** — `camera_attitude` + `camera_position_ned` 로 광선 · 지면 높이 (SIM = UE 지형 · REAL = DEM) · `missing_reasons` · `sync_error_ms` 를 보류 사유로 · 결과는 「worker 주장」 으로만 (공식 승격은 백엔드)
3. **추적 · 상태 · 인상착의** 를 배포 ingest 에 — 통합 담당과 어떤 파일을 바꿀지 합의 (배포 판은 통합 담당이 고친 갈래)
4. 검증 범위 (비전 책임): 탐지 · 후보 연결 · 자동 판정 정확도 · 프레임당 관측 수 · 메시지 크기 제한 → UE 결과로 근거
5. SIM 2 s 간격 → 추적 · 상태 (10 fps 기준으로 만든 것) 에 영향 — 간격 1 s 이하 요청 또는 2 s 용 문턱 다시
