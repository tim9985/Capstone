05 합치려니 우리 라벨의 결함이 드러났다

NOMAD 는 자세 라벨이 아니라 활동 구간(프레임 범위)만 제공한다. make_pose_dataset.py 에서 이렇게 변환했다.

cls = 1 if "Laying" in act else 0    # 구간 안이면 무조건 fallen

구간 경계의 전환 동작 — 눕는 중, 일어나는 중 — 이 전부 fallen 으로 들어간다. 애매한 상태를 처리하지 않았다.

왜 문제인가 반쯤 구부린 자세를 "누움"이라고 배우면 결정 경계가 흐려진다. 운용에서 몸을 굽힌 사람을 계속 쓰러짐으로 오탐하고, 반대로 진짜 쓰러진 자세의 특징은 희석된다. 1·5차 시도가 재현율 0.153 / 0.177 에 머문 원인 중 하나로 의심된다.

SARD-2 는 이 문제를 이미 처리했다

SARD-2 의 not_defined 는 전체의 15.4%(976개) 다. 샘플을 열어보니 웅크림·구부림·엎드림 같은 중간 자세와 가려짐·과소 크기가 섞여 있었고, 클래스별 상자 크기 중앙값도 43 px 로 가장 작다(전체 중앙값 61 px).

제작자가 애매한 것을 억지로 분류하지 않고 별도 라벨로 남긴 것이다. 그리고 그 클래스 자체도 mAP50 0.820 으로 학습이 됐다 — "애매함"은 학습 가능한 범주다.

운용에서의 처리

fallen     → 요구조자 신고 · 지도에 표시
person     → 정상 기록
ambiguous  → 판단 보류 → 스냅샷을 관제 화면으로 (사람이 판단)
이미 있는 설계와 맞물린다 ambiguous 는 SRS 의 FR-V-07(탐지 스냅샷 제공) 과 정확히 대응한다. 모델이 자신 없는 경우를 사람에게 넘기는 안전 장치이고, 재난 탐색에서는 이것이 정직한 설계다.
라벨을 지우면 안 된다 전환 구간을 버리는 것과 ambiguous 로 보내는 것은 다르다. NOMAD 크롭은 1인 1장이라, 라벨만 지우면 모델은 "거기 사람이 없다"고 배운다 — 미탐지를 학습시키는 셈이라 더 나쁘다.

07 팀이 정해야 할 것

각 항목에 조사 결과와 제 의견을 붙였다

D-1WiSARD 13,235개를 어느 클래스로 넣을 것인가
상황
WiSARD 에는 자세 라벨이 없다. 샘플은 대부분 눈밭에서 걷거나 장비를 다루는 구조대원이지만 누운 형태도 섞여 있다.
조사
가로세로비로 걸러 보려 했으나 기준이 성립하지 않았다.
· NOMAD 진짜 fallen 중 59.4% 가 세로로 길다(ar≤1.0) — 하향 시점에선 누워도 각도에 따라 세로로 보인다
· NOMAD fallen 중 ar>1.5 는 17.8% 뿐
· WiSARD 는 ar≤1.0 이 78.9%, ar>1.5 가 8.9% — 어느 쪽으로도 판정 불가
선택지
가) 전부 person — 8.9%의 누운 형태를 "정상"이라 가르침. 요구조자를 놓치는 방향의 오류
나) 전부 ambiguous — 정직하지만 ambiguous 가 최다 클래스(~14,200, 전체의 56%)가 됨
다) 직접 라벨링 — 13,235개는 현실적으로 무리
의견
나) 권장. WiSARD 의 역할은 겨울·눈 도메인에서 사람을 찾는 능력(mAP50 0.922)을 유지하는 것이지 자세를 가르치는 게 아니다. ambiguous 로 들어가도 상자 위치는 정답이므로 탐지 능력은 그대로 학습된다.
D-2전환 구간을 얼마나 잘라낼 것인가
선택지
0.5초 — fallen 89.1% 유지 (97,665개)
1.0초 — fallen 78.6% 유지 (86,103개)
의견
0.5초 권장. 구간 중앙값 7초 대비 충분한 여유이고, 1초까지 자르면 하위 10% 분위(2.0초) 구간이 통째로 사라진다.
D-3seated 를 별도 클래스로 남길 것인가
상황
SARD-2 에서 seated 단독 성능이 mAP50 0.937 / 재현율 0.906 으로 높다. 앉은 사람과 누운 사람의 구분이 1~6차에서 우리가 어려워하던 지점이라, 이 분리가 성공 요인일 가능성이 있다.
문제
NOMAD·WiSARD 에 대응 라벨이 없다. 남기면 SARD-2 에서만 학습되는 클래스가 되고, 다시 도메인 편향이 생긴다.
의견
우선 person 으로 합치기를 권장. 통합 학습 결과 fallen 재현율이 0.7 에 못 미치면 4클래스(person/seated/fallen/ambiguous)로 재시도할 값어치가 있다.
D-4SRS 를 고칠 것인가 — 9/16 발표와 직결
상황
현재 SRS 05절은 자세 자동 판정을 범위 제외로 명시하고 여섯 차례 실패를 근거로 달아 두었다. 그 근거가 뒤집혔다.
선택지
가) 그대로 둔다 — 통합 학습 결과가 아직 없으므로 안전
나) 요구사항으로 승격 — 근거는 재현율 0.972. 다만 도메인 이전이 0.088 인 상태라 위험
다) 조건부로 기술 — "SARD 조건에서 재현율 0.972 확인, 도메인 일반화는 검증 중"
의견
다) 권장. 성과를 숨길 이유가 없고, 한계를 함께 적으면 정직하다. 통합 학습 결과가 나오면 가) 또는 나)로 확정한다.
