# 1. 개요

## 1.1 시스템의 목표

- 고령 인구가 많은 농촌·산지에서 **드론이 자율 정찰하며 사람(쓰러진 사람 포함)을 찾는다**
- 탐지한 사람의 **화면 좌표를 실좌표로 바꿔 관제 지도에 표시**한다
- 운영자는 스냅샷을 보고 대응 여부를 **직접 판단**한다 — 시스템은 후보만 제시

| 목표 | 설계상 의미 |
|---|---|
| 자율 정찰 | 관측 완료도를 계산해 **미관측 영역을 스스로 고른다** (UC-08xx) |
| 사람 탐지 | 누운 사람·부분 가림 포함 **1클래스(person)** · 자세 자동 분류 없음 |
| 좌표 신고 | 박스 아래 변(발끝) 광선–지면 교차로 실좌표 산정 (NFR-V04) |
| 운영자 판단 | 후보 제시 → 운영자 판정 (UC-0705) |

## 1.2 소프트웨어의 주요 기능

| 구분 | 기능 | 대응 UC |
|---|---|---|
| 관제 | 로그인·권한·제어권, 지도·레이어, 임무구역 지정, 알림 | UC-01xx · 03xx · 04xx · 11xx |

# 2. 파일 구조 또는 데이터베이스 설계

## 2.1 주요 엔티티

```
임무(Mission) 1──N 관측지점(Waypoint) 1──N 관측기록(Observation)
     │
     ├──N 프레임(Frame) 1──N 탐지(Detection) N──1 후보(Candidate) 1──N 스냅샷(Snapshot)
     ├──N 명령(Command) 1──N 명령응답(CommandAck)
     ├──N 알림(Alert)
     ├──N 관측칸(GridCell) — 5 m 칸 · 상태 · 관측 누적
     └──1 임무설정(MissionConfig) — 구역 · 고도 · 마운트각 · 렌즈 · 복귀조건 · 실행버전
```

## 2.2 핵심 테이블 `[잠정]` — 관제·비행 테이블은 이시원·서성훈 보완

| 테이블 | 주요 컬럼 | 설계 근거 |
|---|---|---|
| `mission` | id, 구역, 고도, 속도, 복귀조건, **실행버전**, 시작/종료시각, 종료사유 | UC-1201 — 편집본과 실행본 구분 |
| `mission_config` | mission_id, **렌즈(f·화각)**, **마운트각**, 탐지 임계값, 모델 버전 | 좌표 산정·재현에 필요 |
| `frame` | id, mission_id, 프레임식별자, 촬영시각(원본/추정), 기체 위경도·고도·자세, **짐벌각**, 추정방식·불확실성, **수신상태(정상/깨짐/누락 구간)** | UC-0602 — 시각이 추정이면 남긴다 · 깨진 프레임은 분석하지 않음 |
| `detection` | id, frame_id, bbox, 신뢰도, 클래스(person) | UC-0701 |
| `candidate` | id, mission_id, 대표좌표, **오차 타원(거리·옆 σ · 방위)**, **좌표유효/보류 + 보류 사유**, 탐지 횟수, 상의색상 1·2순위, 운영자판정 | UC-0703·0706·0708 · UC-1204 |
| `snapshot` | id, candidate_id, 파일경로, 촬영시각 | UC-0607 |
| `grid_cell` | mission_id, 칸 번호, 상태(미관측·유효·품질부족·가림·제한), **유효 관측 횟수 · 누적 시간**, 마지막 유효 시각 | UC-0802 · 4.4.7 |
| `observation` | id, waypoint_id, 가시영역 폴리곤, 품질등급, 가림여부 | UC-0802 |
| `command` | id, mission_id, 종류, **제어세대**, 유효기간, 검증결과, 거부사유 | UC-0901·0902 |
| `[TBD]` 관제 · 비행 | 사용자 · 권한 · 제어권 · 알림 · 기체 상태 로그 … | 이시원 · 서성훈 |

- 좌표를 못 구한 후보도 **버리지 않고 `좌표보류`로 저장** (UC-1204)
- 짐벌각은 **프레임마다** 기록 — 비행 중 바뀌므로 임무설정 값만으로는 좌표를 못 푼다

# 3. 사용자 인터페이스 설계

| 후보 상세 | 스냅샷, 좌표(유효/보류), 상의 색상, **운영자 판정 입력** | UC-0703·0705 |
| 관측 완료도 | 미관측/유효/품질부족/가림/운용제한 **5색 레이어** · 완료도 % | UC-0803 |
| 알림 | 목록·상세·확인 처리 | UC-1101~1104 |

**비전이 화면에 주는 값** `[확정]` — 표시 방식은 이시원이 정한다

| 값 | 표시 제안 |
|---|---|
| 후보 좌표 + **오차 타원** (거리 방향 σ · 옆 방향 σ · 방위) | 지도 위 점 + 타원 (1σ) — 점만 찍으면 정확해 보여 오해를 산다 |

| 신뢰도 · 탐지 횟수 | 숫자 · 여러 번 잡힐수록 진한 표시 |
| 관측 칸 상태 | 5색 격자 (4.4.7) |

### 4.4.5 상의 색상 (`ColorProfiler`) `[잠정]`

- 박스 위쪽 30~60 % 구간(상의)에서 배경을 뺀 화소 → Lab 색공간 → 12색 중 가까운 1·2순위
- 60° 비스듬 시점은 몸 옆모습이 보여 수직보다 상의가 넓게 잡힌다

### 4.4.6 좌표 산정 (`GeoResolver`) `[확정]` — 구현 `geo_resolver.py`

- 박스 **아래 변 가운데(발끝)** 를 지면 접촉점으로 본다 — 몸 중심은 지면 위라 더 멀게 나온다
- 깊이 센서 없이 **광선과 지면(이륙점 높이 · 지형 자료가 있으면 지형)의 교차점**

```
f = (W/2) / tan(HFOV/2)                 88° 렌즈: f = 1,141 px
광선 = R(기체 방위 · 짐벌 피치·방위) · (1, (u−W/2)/f, (v−H/2)/f)      짐벌 안정화 시 기체 roll·pitch 제외
교차 t = 고도 / 광선_아래성분 → (북, 동) = t · (광선_북, 광선_동) → 기체 위경도에 더한다
```

| 좌표보류 조건 | 이유 |
|---|---|
| 발끝이 화면 아래 끝에 걸림 | 발이 잘렸을 수 있어 거리를 짧게 잡는다 |
| 광선이 지평선 위 · 200 m 초과 | 교차점이 없거나 믿을 수 없음 |
| 기체 기울기 > 6° · 자세 변화 > 1.5°/프레임 | NFR-V04 안정 프레임 조건 |

**오차** — 합성 장면 4,000 표본 (GPS 1.5 m · 고도 1 m · 짐벌 피치 1° · 방위 2° · 1σ · 지형 기복 제외)

| 마운트 | 16 m | 20 m | 25 m | 30 m |
|---|---|---|---|---|
| 45° | 2.3 / 5.2 | 2.3 / 5.5 | 2.5 / 6.0 | 2.5 / 6.2 |
| **60°** | **2.0 / 4.2** | 2.0 / 4.5 | 2.0 / 4.0 | 2.1 / 4.7 |
| 75° | 1.8 / 3.9 | 1.9 / 4.2 | 1.9 / 4.1 | 2.0 / 3.9 |

중앙 / P95 (m) · 오차 없는 입력에서 계산 오차 0 (식 검증)

- 지형 기복을 넣은 예산 (25 m · 화면 중앙 · GPS 3 m · 짐벌 2° · 고도 3 m · 기복 5 m): 60° **4.7 m** · 45° 6.8 m · 30° 11.1 m ⚠️
- 오차를 좌우하는 것은 짐벌각보다 **지형 기복** — 산지에서는 지형 자료(DEM) 반영
- 검증 계획: UE 시뮬레이터 (정답 좌표 · 탐지 박스로 계산) → 첫 비행에서 좌표를 찍은 지점과 비교 (NFR-V04 시험)

### 4.4.7 관측 완료도 · 관측 시간 `[잠정]` — 비행(서성훈) · 관제(이시원) 와 공동

- 임무구역을 **5 m 칸**으로 나누고, 프레임마다 화면이 덮는 칸을 CameraModel 로 계산해 누적한다
- 품질 부족 · 가림 · 운용 제한은 **분모에서 빼되 사유를 남긴다** (UC-0804)
- **관측 완료 조건 (제안) = 유효 품질로 3 초 이상 화면 안** — 같은 사람을 약 1 초 간격으로 여러 번 볼 때 한 번 이상 찾을 확률 (최종 모델 · test_obl 추적 ID 실측)

| 본 횟수 (첫 관측 후) | 1회 (0 s) | 2회 (0.9 s) | **3회 (1.7 s)** | 4회 (2.6 s) | 6회 (4.4 s) |
|---|---|---|---|---|---|
| 찾을 확률 (IoU 0.5) | 0.69 | 0.80 | **0.84** | 0.87 | 0.90 |
| 찾을 확률 (위치 대략 · IoU 0.3) | 0.85 | 0.90 | **0.92** | 0.93 | 0.94 |
| 가려진 사람 (IoU 0.5) | 0.24 | 0.45 | 0.58 | 0.68 | 0.80 |

- 연속 프레임은 서로 닮아(같은 가림·자세) 한 장 확률로 곱하면 과장된다 (3회 0.97 ↔ 실측 0.84) → **관측 1회 = 약 1 초**
- 가림이 많은 칸(숲 가장자리)은 5 초 이상 · 다른 방향에서 한 번 더 · 수관 아래는 "가시성 미확인"

|---|---|---|---|---|---|
| 16 m | 21.8 m | 7.3 s | 4.4 s | 2.7 s | 7.3 m/s |
| 20 m | 27.3 m | 9.1 s | 5.5 s | 3.4 s | 9.1 m/s |
| 30 m | 41.0 m | 13.7 s | 8.2 s | 5.1 s | 13.7 m/s |

### 4.4.8 영상 수신 · 프레임 손실 `[제안]` — 서성훈 확인

- 탐지 성능은 **한 장의 화질(해상도 · 압축)** 에 달렸고 초당 장수와는 무관 → **1920×1080 유지 · 초당 10장**
- 전송량이 같다면 장수를 줄인 만큼 한 장 화질이 오른다 · 흔들림 번짐은 셔터(1/1000 s)가 정한다
- H.264 는 패킷 손실 시 다음 키프레임까지 화면이 **깨진다** → 깨진 프레임은 분석하지 않고 손실로 처리 · 키프레임 약 1 초

| 초당 수신 | 평균 손실 허용 (20 m · 5 m/s · 한 칸 3 초 관측 99 %) | 연속 끊김 허용 |
|---|---|---|
| 5장 | 63 % | 체류 − 3 초 — 16 m · 5 m/s **1.4 초** · 20 m 2.5 초 · 30 m 5.2 초 |
| **10장** | **79 %** | 〃 |

- 기준 (제안): 평균 손실 **50 % 이하** · 연속 끊김 **1 초 이하** · 1 초 넘는 끊김 구간은 기록해 그 사이 칸은 미관측

### 4.4.9 인터페이스 — vision 이 받는 것 · 주는 것 `[잠정]`

| 장소 분리 | 학습에 쓴 장소를 평가에 쓰지 않는 분할 |
| 좌표보류 | 탐지는 됐으나 발끝이 안 보이는 등으로 좌표를 믿을 수 없는 후보 · 버리지 않고 사유와 저장 |
| 오차 타원 | 후보 좌표의 불확실성 — 거리 방향 · 옆 방향 1σ (m) |
| 관측 1회 | 약 1 초 — 같은 1 초 안의 여러 프레임은 거의 같은 장면이라 1회로 센다 |
| 키프레임 | 다른 프레임에 기대지 않고 한 장으로 복원되는 H.264 프레임 · 손실 뒤 화면이 여기서 회복 |
| 짝 부트스트랩 | 두 모델을 같은 표본(연속 20장 묶음)으로 반복 재표집해 AP 차이의 95 % 구간을 구하는 판정 |
| 가중치 평균 (수프) | 같은 출발점에서 따로 학습한 모델들의 가중치를 평균해 모델 하나로 만드는 것 |
| 제어세대 | 제어권이 바뀔 때마다 증가하는 번호. 오래된 명령 폐기 기준 |
