# 문제 정의 재검토 — 데이터 표현 · 문제 표현 · 목적함수 · 최적화

> 자율 정찰 드론 관제 시스템 · 사람 탐지 · 2026-09-19
> 현재 구현을 네 축으로 다시 세우고, **측정된 사실 / 계산 / 미확인 제안**을 구분해 적는다.
> 진행 현황과 실험 수치는 [[교수님_상담용_비전_학습_요약]] 에 있다.

## 요지

현재 구현은 **프레임 단위 객체 탐지** 문제로 세워져 있다. 실제 과업은 **한 번의 비행에서 구역 안의 사람을 찾는 탐색**이다.
이 단위 차이 때문에 학습 손실 · 모델 선택 지표 · 합격 기준 · 실제 목적이 서로 다른 대상 위에 정의되어 있다.

| 층 | 현재 정의 | 정의된 대상 |
|---|---|---|
| 학습 손실 | CIoU + BCE + DFL | 크롭 배치 |
| 모델 선택 | fitness = mAP50-95 | 16~160 px 혼합 val |
| 합격 기준 | AP50 ≥ 0.80 (장소 분리) | 프레임 |
| 실제 목적 | — | **정의된 적 없음** |

# 1. 데이터 표현

## 1.1 현재

```
x = 1280×720 크롭 1장 (RGB)      ← 1920×1080 원본에서 1:1 배율로 오려냄
y = 사람 박스 목록 (1클래스)
```

전처리에서 원본을 리샘플해 **사람 긴 변이 로그 균등 16~160 px**가 되도록 맞춘 뒤 창을 뜬다.

## 1.2 입력에서 빠져 있는 정보 — 기하

추론 시점에 **고도 · 화각 · 자세를 알 수 있다.** 이 값이 정해지면 사람의 픽셀 크기가 거의 결정된다.

```
px = (1920/2) / tan(화각/2) × 대상 길이 / 고도
```

| 조건 | 서 있는 사람 (0.81 m) |
|---|---:|
| 75° · 25 m | 41 px |
| 75° · 30 m | 34 px |
| 90° · 30 m | 26 px |

**현재 구조에서는 이 정보를 모델에 주지 않고**, 16~160 px 전 범위에 강건하도록 학습시킨다.

### 관찰된 불일치

- **학습**: 크롭을 목표 px로 **리샘플해서** 만든다
- **추론**: 원본 1920 프레임을 **그대로** 넣는다

즉 학습 단계에서 수행한 크기 정규화를 추론 단계에서는 하지 않는다.

### 미확인 제안 — GSD 정규화

고도를 아는 상태이므로, 추론 전에 프레임을 리샘플해 **사람이 항상 일정 px(예: 60 px)** 가 되게 맞출 수 있다.
그 경우 탐지기가 다루는 크기 범위가 좁아진다. 효과는 측정되지 않았다.

## 1.3 입력에서 빠져 있는 정보 — 시간

**계산** (지상 세로폭 = 1080 × 고도 / f, 5 FPS 기준)

| 화각 | 고도 | 지상 세로폭 | 3 m/s | 5 m/s |
|---|---|---:|---:|---:|
| 75° | 25 m | 21.6 m | 36 프레임 | 22 |
| 75° | 30 m | 25.9 m | 43 | 26 |
| 90° | 30 m | 33.7 m | 56 | 34 |

한 사람이 화면에 **20~56 프레임** 머문다. 현재는 각 프레임을 독립 문제로 처리하며 프레임 간 정보를 쓰지 않는다.

## 1.4 출력 표현

최종 산출물은 박스가 아니라 **실좌표 + 인상착의(상의 색상)** 이다. 박스는 중간 표현이다.
정사 보정된 지면 좌표계 위의 표현을 쓰면 여러 프레임의 관측을 같은 좌표계에서 누적할 수 있다 (미확인 제안).

# 2. 문제 표현

## 2.1 현재

프레임 단위 단일 클래스 객체 탐지. 평가도 프레임 단위 AP50 · 재현율.

## 2.2 과업의 실제 단위

한 번의 비행에서 구역 안의 사람을 찾는 것이므로, 단위는 **사람 × 임무**이다.

### 프레임 재현율과 임무 발견율의 관계 (계산)

프레임 재현율 `r = 0.34` 일 때, 유효 시도 수 `k_eff` 에 따른 `1 − (1−r)^k`:

| k_eff | 1 | 2 | 3 | 5 | 10 |
|---|---:|---:|---:|---:|---:|
| 발견율 | 0.340 | 0.564 | 0.713 | 0.875 | 0.984 |

- 노출 프레임은 20~56장이지만, **프레임 간 상관이 크다** (같은 사람 · 같은 배경 · 유사 각도)
- 따라서 `k_eff` 는 노출 프레임 수보다 훨씬 작다. **값은 측정되지 않았다**
- `k_eff` 가 3~5라면 프레임 0.34는 임무 0.71~0.88에 해당한다

### 오탐은 반대 방향으로 누적된다 (계산)

| 프레임당 오탐 | 15분 · 5 FPS (4,500프레임) |
|---|---:|
| 0.35건 | **1,575건** |
| 0.50건 | 2,250건 |

현재 측정값 0.33~0.54건/프레임은 NFR-V06(≤1건/프레임)을 충족하지만, 임무 전체로는 수천 건이 된다.
즉 **프레임 단위 기준의 충족이 운용 가능성을 보장하지 않는다.**

## 2.3 다시 쓴 문제 (제안)

> 구역 안 각 사람에 대해 **임무 중 한 번 이상 올바른 위치로 보고할 확률**을 최대화한다.
> 제약: 운영자 확인 대상 후보 건수 ≤ 예산, 프레임 지연 ≤ 30 ms

이 형태에서 프레임 탐지는 하위 부품이 되고, **시공간 집계**가 구성 요소로 들어온다.

# 3. 목적함수 / 검증

## 3.1 측정된 불일치 사례

동일 데이터 · 동일 설정으로 학습한 yolo11m 과 yolo11l 비교:

| 비교 기준 | yolo11m | yolo11l |
|---|---:|---:|
| val mAP50 (16~160 px 혼합) | 0.4510 | **0.4732** |
| 가림 지형 AP50 (18칸) | **전부 우위** | 전부 열세 (−0.7 ~ −19.5 %) |

크기 구간별 재현율@0.15 (val 1,600장 · 동일 정답):

| 대상 크기 | 정답 수 | 11m | 11l |
|---|---:|---:|---:|
| 16~25 px | 262 | 0.160 | 0.191 |
| 25~40 px | 502 | **0.217** | 0.187 |
| 40~60 px | 614 | **0.366** | 0.347 |
| 60~100 px | 808 | **0.556** | 0.540 |
| 100~300 px | 636 | **0.734** | 0.719 |
| 프레임당 오탐 | — | 0.542 | **0.439** |

yolo11l 은 16~25 px 를 제외한 전 구간에서 재현율이 낮고 오탐이 19 % 적다.
AP 는 정밀도를 함께 반영하므로 오탐이 적은 쪽이 유리하게 계산된다.
설계 우선순위는 **미탐 최소화 > 오탐 최소화** 이고, 오탐은 이미 NFR-V06 을 충족한 상태이다.

**단일 지표 사용 시의 역전**: 가림 지형 40 m(18 px) 칸에서 11l 의 재현율@0.15 는 +9.5 %, 같은 칸 AP50 은 −19.5 % 였다.

## 3.2 검증 조건의 결함

| 데이터 | 분할 단위 | 장소 분리 |
|---|---|---|
| NOMAD | 배우 | 불가 (촬영지 1곳) |
| WiSARD | 비행 | **미충족** — val 장소 6곳이 train 에도 존재 |
| AI-Hub | 장소 | 충족 (다만 가림이 없어 난이도가 낮음) |

NFR-V03 은 장소 분리를 요구하나 현재 어느 시험셋도 이를 만족하지 않는다.

## 3.3 다시 세운 정의 (제안)

| 층 | 정의 |
|---|---|
| 운영 목표 | 임무 발견율 ≥ T · 운영자 확인 건수 ≤ B |
| 연결 | 프레임 재현율 r · 유효 시도 수 k_eff · 집계 규칙 → 발견율 추정 |
| 프레임 대리지표 | 1차 **운용 크기 구간(18~50 px) 재현율@0.15** · 2차 **같은 구간 AP50** · 3차 오탐(통과/탈락 관문) |
| 검증 축 | 단일 스칼라가 아니라 **크기 × 가림 × 지형 × 장소** 층화 |

**확인이 필요한 항목**: NFR-V03 의 "AP50 0.80" 이 임무 요구에서 유도된 값인지 여부.
임무 발견율 기준으로 환산하면 요구 수준이 달라질 수 있다.

# 4. 최적화

## 4.1 현재

가중치는 SGD 로 최적화하고, 모델 크기·하이퍼파라미터는 수동 탐색한다.

## 4.2 측정된 포화

| 학습 | 데이터 | 정점 | 최종 |
|---|---|---|---:|
| yolo11s (30 epoch) | 30,056장 | 25에폭 0.4224 | 0.3987 (−5.6 %) |
| yolo11m (19 epoch) | 30,056장 | 13에폭 0.4510 | 0.4264 (−5.5 %) |
| yolo11l (30 epoch) | 30,056장 | 20에폭 0.4732 | 0.4265 (−9.9 %) |
| yolo11l (L2, 진행 중) | **49,268장** | 16에폭 0.4791 | 아직 감소 없음 |

- 세 학습 모두 중반에 정점 후 감소했다
- 모델 확대(11m → 11l)는 운용 구간에서 성능이 낮았다 (§3.1)
- 데이터를 64 % 늘린 L2 는 같은 에폭 구간에서 감소가 나타나지 않았다

## 4.3 층별 레버

| 층 | 변수 | 확인된 효과 |
|---|---|---|
| 학습 | 가중치 · 에폭 · 모델 크기 | 포화 · 확대는 역효과 |
| **데이터** | 무엇을 더 모을 것인가 | L2 에서 과적합 지연 관찰 (진행 중) |
| **표현** | GSD 정규화 · 시간 누적 | **미측정** |
| 추론 | 해상도 · 타일 · 집계 | 해상도 1280 → 1920 에서 38 px 대상 **+21.6 %** |

추론 해상도 변경(+21.6 %)이 모델 확대(음의 효과)보다 큰 이득을 냈다.

# 5. 상담에서 확인하고자 하는 것

**① 문제 단위** — 프레임 탐지에서 임무 탐색으로 단위를 올리는 것이 타당한가. 그렇다면 NFR-V03(프레임 AP50 0.80)을 임무 발견율 기준으로 재정의해야 하는가.

**② 기하 정보의 사용** — 고도·화각을 알고 있으므로 입력을 GSD 정규화하는 방식과, 현재처럼 크기 범위 전체에 강건하게 학습하는 방식 중 어느 쪽이 적절한가.

**③ 시간 정보의 위치** — 다중 프레임 정보를 탐지 후 집계(후처리)로 둘지, 입력 표현 단계로 끌어올릴지.

**④ 데이터 선택 기준** — 데이터가 천장인 상황에서 무엇을 더 모을지 고르는 기준(능동 학습 · 난이도 기반 수집 등).

# 6. 미팅 전에 측정 가능한 항목

| | 측정 | 방법 | 소요 |
|---|---|---|---|
| **A** | **유효 시도 수 k_eff** | NOMAD val 배우별 · WiSARD val 비행별로 연속 프레임을 묶어, 프레임 재현율과 "구간 내 1회 이상 탐지 확률"을 함께 산출 | 반나절 |
| **B** | **GSD 정규화 효과** | 전체 프레임 시험셋을 사람이 일정 px 가 되도록 리샘플해 추론, 현재 방식과 비교 | 2시간 |

둘 다 기존 가중치로 가능하며 재학습이 필요하지 않다.
A 는 §2.2 의 `k_eff` 를, B 는 §1.2 의 정규화 불일치를 각각 수치로 만든다.
