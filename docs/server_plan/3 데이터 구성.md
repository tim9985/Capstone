## 2. WiSARD 비행별 각도 분류 — 가장 먼저

노트북에서 확인한 10개 비행만 봐도 하향·비스듬·측면·야간이 섞여 있었다 → [[학습 데이터 촬영 각도 불일치]].
서버에는 전체 비행이 있으니 **전부 분류한 표**를 먼저 만든다.

1. 비행마다 시간 균등 12장을 뽑아 모음판 한 장으로 만든다 (새 스크립트 `flight_sheet.py`)
2. 눈으로 보고 `configs/wisard_flight_tags.csv` 에 기록

| 열 | 값 |
|---|---|
| `flight` | 폴더 이름 |
| `month` | 09 / 01 … |
| `view` | `nadir`(거의 하향 · 약 75° 이상) · `tilted`(45~75°) · `oblique`(45° 미만) · `side`(수평 측면) |
| `light` | `day` · `dusk` · `night` |
| `terrain` | 숲 · 초지 · 설원 · 도로 … |
| `people` | 있음 / 없음 (음성 비행) |

3. `wisard_prep.py` 에 `--tags` · `--views nadir,tilted` 옵션 추가
4. **`night` 는 가시광 학습에서 제외** (거의 검은 화면 — 우리 시연은 주간)

## 3. 각도별 섞는 비율 — 마운트 결정에 달렸다

요구명세서 NFR-H02 는 "무짐벌 **하향 30~90°** 지원" 이다. 마운트 각도가 정해지지 않았다 → [[1 기준 조건 - 카메라·화각·마운트]]

| 마운트 결정 | nadir | tilted | oblique | side |
|---|---:|---:|---:|---:|
| **90° 고정** (현재안) | ×2 | ×1.5 | ×1 | ×0.5 |
| 45~60° | ×1 | ×2 | ×1.5 | ×0.5 |
| 미정 (지금) | ×1.5 | ×1.5 | ×1 | ×0.5 |

- ultralytics 에는 샘플 가중치가 없다 → **이미지 목록 파일에 반복해 넣는다** (`train_person.py` stage2 가 합성 데이터를 3배 넣은 것과 같은 방식)
- 0.5 는 "절반만 무작위로 넣는다"
- side(1월 Baker)는 겨울·설경 다양성 때문에 **빼지 않는다**. 대신 겨울 성능 근거로 쓰지 않는다 → [[겨울 0.922의 한계]]

## 4. NOMAD

| 항목 | 프로토타입 | 실기체용 | 이유 |
|---|---|---|---|
| 배우 | 1~30 | **60명** (train 48 / val 12) | 서버 현재 구성 유지 |
| 거리 | 10 · 30 m | **10 · 30 · 50 m** (+70 m 표본 추가) | 작은 사람 목표(20~40 px)는 먼 거리 원본에서 만들어야 확대가 없다 → [[4 전처리 - 크기 정규화와 지터]] |
| 원본 1장당 크롭 | 1 | 1 (50·70 m 는 2) | 먼 거리는 사람이 작아 한 장에서 여러 창을 뽑아도 겹침이 적다 |
| 누운 사람 비중 | 20.7% | **40%** | 과제가 쓰러진 사람 찾기. `activityLabels.json` 의 Laying·Hiding(Laying) 구간을 더 자주 뽑는다 |
| 가시도 | 전부 | 전부 (가시도 기록) | 부분 가림도 찾아야 한다. 평가에서 가시도별로 나눠 본다 |

> [!warning] 분할은 배우 단위를 유지한다
> 프레임 단위로 섞으면 같은 장면이 학습·검증 양쪽에 들어가 성능이 부풀려진다.

## 5. SARD 를 탐지 학습에 넣는 이유

- **누운 사람이 1,096개** — 사람이 직접 붙인 라벨이라 NOMAD(활동 구간에서 유도)보다 정확하다
- 채석장·풀밭·숲·도로 — 농장 한 곳(NOMAD)보다 배경이 다양하다
- 1클래스 탐지에서는 자세를 무시하고 전부 `person` 으로 쓴다 (`not_defined` 도 사람으로)

> [!warning] SARD 확인할 것
> 1. Roboflow 재배포본의 **해상도** — 축소돼 있으면 작은 사람 목표로만 쓴다
> 2. train/valid/test 가 **프레임 무작위 분할**이면 같은 장면이 양쪽에 있다 → valid·test 수치는 참고만
> 3. 촬영 각도 — WiSARD 와 같은 방식으로 모음판 확인

## 6. 음성(사람 없는) 이미지

오탐(NFR-V06)을 줄이려면 **사람이 없는 장면**도 배워야 한다.

| 출처 | 방법 | 비율 |
|---|---|---|
| NOMAD | 사람 박스에서 멀리 떨어진 영역만 잘라낸 크롭 | 전체의 약 5% |
| WiSARD | 사람 없는 프레임 (9월 val 앞쪽 291장 같은 구간) | 약 5% |
| 자체 촬영 | 사람 없이 같은 경로 비행 | 자체 데이터의 20% |
| **합계** | | **전체의 10~15%** |

라벨 파일을 **빈 파일**로 두면 ultralytics 가 배경 이미지로 학습한다.

## 7. AI-Hub 182 — 신청 후 표본 분석

「드론 이동체 인지 영상(도로 고정)」에 **조난자 수색** 시나리오와 `사람(누워있음·서 있음·앉아 있음)` 라벨이 있다. 한국 데이터라 가장 탐나지만 **촬영 각도·고도가 페이지에 없다**.

1. 사용자가 AI-Hub 에서 신청 (로그인·신청은 직접)
2. 샘플 JSON 에서 `angle` · `altitude` 필드 분포를 뽑는다
3. 하향 60° 이상 · 고도 10~40 m 인 부분만 쓸 수 있는지 판단
4. 쓰게 되면 **git 에 올리지 않는다** (AI-Hub 약관)

> [!note] 예전에 기각한 AI-Hub 데이터는 `dataSetSn=190` (촬영각 45°) 이다. 182 는 아직 판정 전이다.
